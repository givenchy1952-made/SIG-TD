# 생산 조건·PO·차수 단가·원부자재 컨펌

2026-10-30 생산 업무 개선 안내입니다. 프로젝트 명칭·코드 필터와 다운로드 개선은 [프로젝트 명칭 안내](PROJECT_NAMES.md)를 참고하세요.

## 생산 조건 협의·승인에서 PO 보내기

스타일 상세의 **생산 조건 협의·승인**에서 프로젝트·생산 차수를 선택하고 PO를 작성·확인·발송합니다. 같은 화면에서 발주 내용과 업체 회신, 본사 검토·승인을 이어서 확인합니다.

1. **프로젝트 코드 · 공식 명칭**에서 프로젝트를 선택하고 **생산 차수 · 품번·컬러·수량**을 확인합니다.
2. **이 차수 PO 작성**에서 수신인·본사 요청 납기·본문·첨부파일을 확인한 뒤 **차수 PO 초안 저장 및 연결**을 누릅니다.
3. 같은 화면 아래 **PO 메일 및 발송 이력**에서 해당 차수의 PO를 확인하고 **PO 메일 발송 → 발송 확인**을 누릅니다.
4. 이전 자료는 **전체 PO 이력**에서 확인합니다. 별도 PO 탭은 통합되어 표시되지 않습니다.

프로젝트 코드만으로 이름이 비슷한 PO를 추정해 연결하지 않습니다. 선택한 생산 차수의 프로젝트 ID·컬러·사이즈 수량을 기준으로 PO 초안을 만들고, 기존 발주 생성 RPC에서 해당 차수에 연결합니다. 초안을 저장해도 메일은 발송되지 않으며 수신인과 내용을 확인한 뒤 발송을 확정해야 합니다.

기존 PO 초안·발송 접수·시도·연결 기록은 유지합니다. 이미 발송한 문서의 내용은 덮어쓰지 않습니다. 별도로 발송한 기존 PO를 차수에 연결할 때도 실제 문서의 프로젝트·전체 품번·컬러·업체·수량을 확인하는 기존 절차를 사용합니다.

새 PO 본문의 업체 접속 링크는 공개 주소 `https://sig-td.vercel.app`을 사용합니다. 다른 공개 사이트를 운영할 때는 `.env.example`의 `VITE_PUBLIC_APP_URL`을 설정합니다. 배포 미리보기 주소가 메일에 들어가는 일을 막으며, Microsoft 로그인 콜백 주소와 기존 발송 문서는 변경하지 않습니다.

## 생산 차수·마감에서 프로젝트 코드로 찾기

**생산 차수·마감**의 프로젝트 명칭 선택과 프로젝트 코드 필터로 원하는 차수를 좁힙니다. 같은 프로젝트 명칭이라도 선택 값은 기존 프로젝트 ID이며, 코드 조건과 함께 적용합니다. 필터는 조회·다운로드 범위를 바꾸며 프로젝트·스타일·차수의 연결 자체를 변경하지 않습니다.

## 생산 차수·마감에서 단가 입력하기

생산 차수 화면에서 **본사 검토 단가 입력·수정**을 열어 생산 방식과 검토 단가·사유를 저장합니다. 차수명·프로젝트·수량을 편집 중이면 해당 변경을 먼저 저장한 뒤 단가를 입력합니다.

이 단가는 **생산 조건 협의·승인**과 공유하는 본사 내부 검토 기준입니다. 업체에 공개되지 않으며, 단가 입력만으로 생산이 시작되거나 마감 금액이 바뀌지 않습니다. 본사가 업체 제안을 최종 승인할 때 확정 생산 단가가 반영됩니다. 빈칸은 미입력이고 `0`은 0원입니다.

승인·마감된 차수의 단가는 이 화면에서 수정하지 않습니다. 확정 단가·실입고·을지 금액·부가세·합계는 기존 승인·마감 기록을 사용하며, 조건 변경은 별도 차수와 재승인 절차를 따릅니다. 발송 또는 회신 이력이 있는 생산 방식도 유지합니다.

## 원부자재 컨펌 기록

메인 생산에서 원단·단추·지퍼 등 확인할 원부자재를 개별 항목으로 등록하고 항목별 컨펌 차수를 기록합니다. 각 차수의 코멘트와 첨부 자료를 보관하며, 리젝된 경우 이전 차수를 덮어쓰지 않고 다음 차수로 다시 제출합니다.

1. **스타일 상세 → 메인 생산**에서 컬러를 선택하고 **원·부자재 세부 컨펌**을 엽니다.
2. 본사는 **원·부자재 항목 추가**에서 원단/부자재 구분, 항목명, 사양과 기록 사유를 입력해 **원·부자재 항목 저장**을 누릅니다.
3. 해당 품목의 **1차 컨펌 요청**에서 코멘트와 사진을 준비하고 **원·부자재 컨펌 요청 저장**을 누릅니다. 배정 업체도 자신의 스타일에서 요청할 수 있습니다.
4. 사진은 **이미지 업로드** 후 목록에서 이번 회차에 사용할 이미지를 선택합니다. JPG·PNG·WEBP 파일을 한 장당 10MB까지 올릴 수 있으며, 한 번의 요청 또는 검토에 최대 12장을 연결합니다. 코멘트 또는 사진 중 하나 이상과 기록 사유가 필요합니다.
5. 본사는 대기 회차의 **1차 확정** 또는 **1차 리젝**을 눌러 검토 코멘트·사진·사유를 남기고 **원·부자재 검토 확정**을 누릅니다. 요청자가 제출한 코멘트와 사진은 유지하고 본사 검토를 별도로 표시합니다.
6. 리젝 후 **2차 컨펌 요청**, 다시 리젝되면 **3차 컨펌 요청**으로 이어집니다. 본사 판정 대기 중에는 다음 회차를 중복 제출하지 않습니다.

본사는 이미 검토한 결과를 **기록 상태 → 검토 완료 기록 · 확정/리젝**으로 새 회차에 직접 기록할 수도 있습니다. 기존 확정 회차를 다시 검토해야 할 때는 본사가 새 회차를 시작하며 업체가 확정된 결과를 바꾸지는 못합니다.

**컨펌 이력**에는 회차별 요청·판정 상태, 당시 항목명·사양, 코멘트·이미지, 요청자·검토자와 시각을 표시합니다. 과거 결과를 삭제하거나 같은 확정 회차를 덮어쓰는 편집 기능은 제공하지 않습니다. 이전 사진은 각 회차에서 미리보기와 다운로드로 확인합니다.

확정 후 항목명·구분·사양을 바꾸면 **항목 정보 변경 · 재컨펌 필요**를 표시합니다. 이전 회차는 당시 사양의 결과로 보존하며, 변경한 사양의 확정으로 표시하지 않습니다.

기존 **원·부자재** 체크리스트는 유지됩니다. 세부 항목의 확정·리젝을 입력해도 이 종합 체크를 임의로 변경하거나 생산 조건 최종 승인을 대신하지 않습니다. 한 스타일에 최대 200개 항목, 항목별 최대 100차를 기록할 수 있습니다.

## 추가 SQL 적용 범위

PO 화면 통합, 프로젝트 코드 필터와 본사 검토 단가 입력은 기존 데이터 구조와 RPC를 사용합니다. 기존 사용자·공장 권한이나 최종 승인 규칙을 바꾸지 않습니다.

원부자재의 개별 항목·차수·판정·코멘트·첨부 아카이브를 여러 사용자가 공유하려면 신규 [017_material_reviews.sql](../supabase/migrations/017_material_reviews.sql)이 필요합니다. 기존 `016_partial_delivery_plans.sql`은 분납 계획용이며 원부자재 기능 SQL과 별개입니다. 이미 적용된 SQL을 재작성하거나 초기화하지 않습니다.

017 SQL은 이 개발 작업에서 운영에 자동 실행하지 않습니다. 적용 전 최종 파일과 변경 범위를 확인한 뒤 Supabase SQL Editor에서 **017 파일만** 직접 실행하고, 새 앱 배포 후 화면을 새로고침합니다. 016까지 설치되지 않은 프로젝트는 미적용 후속 파일을 번호 순서대로 검토합니다. 운영 프로젝트에는 예시 시드나 초기화 SQL을 실행하지 않습니다.

원부자재 SQL 적용 전에도 기존 스타일·PO·협의·마감 화면은 유지하며, 신규 원부자재 화면은 준비 안내를 표시합니다.

| 기능 | 저장 구조·SQL |
| --- | --- |
| 협의 화면의 PO 작성·발송 | 기존 PO·생산 차수·연결 RPC 사용, 추가 SQL 없음 |
| 생산 차수의 프로젝트 코드 필터 | 조회 범위만 변경, 추가 SQL 없음 |
| 생산 차수의 본사 검토 단가 입력 | 기존 생산 조건 검토 기준 저장 RPC 사용, 추가 SQL 없음 |
| 원부자재 세부 컨펌 | 017의 항목·회차·이미지 참조·변경 이벤트 테이블과 저장·제출·판정 RPC 사용 |

017의 신규 테이블은 `material_review_items`, `material_review_rounds`, `material_review_attachments`, `material_review_events`입니다. 클라이언트 직접 쓰기를 허용하지 않고 승인된 활성 계정의 RPC로 변경합니다. 본사는 항목 등록·수정과 확정·리젝을 담당하며, 외부 공장은 기존 배정 스타일에서 조회·컨펌 요청만 수행합니다. 다른 공장의 자료나 본사 내부 단가 조회 권한을 추가하지 않습니다.

회차에 연결된 이미지의 메타데이터와 저장소 파일은 원부자재 아카이브 참조로 보호합니다. 원본 요청 자료를 다른 파일로 교체하거나 확정 회차·참조를 삭제해 이력을 없애는 작업은 거부합니다. 기존 PO·입출고·분납·본사 승인·마감 자료는 이 기능으로 초기화하거나 재계산하지 않습니다.
