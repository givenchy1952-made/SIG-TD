## 가입과 승인

Supabase **Authentication → Sign In / Providers → Email → Confirm email**을 OFF로 저장합니다. SQL이나 앱 배포로 이 설정이 바뀌지는 않습니다. 비밀번호 재설정에는 메일을 계속 사용하므로 Site URL·Redirect URLs·메일 발송 설정을 유지하세요.

가입 요청 후에는 업무 화면에 들어가지 않습니다. 관리자 또는 본사 직원이 **사용자·기본 설정 → 사용자 관리**에서 승인하고 역할을 지정합니다. 외부 공장은 등록된 소속 공장도 반드시 선택해야 합니다. 승인·활성·공장 배정이 완료된 후 다시 로그인합니다.

본사 직원은 신규 본사 가입자와 공장 계정을 승인하고 공장 소속을 관리할 수 있습니다. 관리자 역할 부여, 관리자 계정 변경, 이미 승인된 본사 계정의 권한 변경은 관리자만 가능합니다. 현재 관리자는 본인의 관리자 권한을 직접 해제할 수 없습니다. 관리자 이관은 요청한 시점에 직접 진행하며 예약하거나 지금 변경하지 않습니다.

## 오더에서 생산 동의까지

1. 본사에서 ORDER QTY 파일을 업로드합니다. 적용한 품번·컬러마다 새 생산 차수가 생깁니다. A열 프로젝트 코드, M열 명칭, L열 시즌이 등록된 프로젝트와 일치해야 합니다.
2. **메인 생산 → 프로젝트·생산 차수별 현황 → 상세 → 업체 납기·동의**에서 해당 프로젝트와 차수를 선택합니다.
3. 본사에서 해당 차수의 **PO 작성**으로 수신 업체 이메일, 요청 납기, 제목·본문을 확인하고 초안을 저장합니다. 이후 **PO** 탭의 발송 내용을 확인해 메일을 발송합니다. 초안 저장과 실제 발송 접수는 별도 상태입니다.
4. 업체 담당자는 자신의 승인된 공장 계정으로 로그인해 발송된 PO와 사이즈별 발주 수량을 확인합니다. **업체 예상 납기일**을 입력하고 **생산 동의**에 체크해 제출합니다. 제출과 동시에 해당 차수가 생산 진행으로 전환됩니다.
5. 동의 당시의 프로젝트·품번·차수·수량, PO 제목·본문·요청 납기·발송 정보, 업체 예상 납기, 제출 계정·공장·시각을 보존합니다. 이미 동의한 조건은 덮어쓰지 않고 새 PO·새 차수로 관리합니다.

PO 메일 발송에는 기존 `send-po-email` Edge Function과 발신 서비스 설정이 필요합니다. 파일 업로드나 초안 저장만으로 메일이 발송되지는 않습니다. 실제 발송 접수 여부는 PO 이력에서 확인하세요. 관련 설정은 [메일 서비스 가이드](OPERATIONS_SETUP.md)를 참고하세요. 이력은 업무 확인 자료이며 공인 전자서명 서비스의 서명을 생성하는 기능은 아닙니다.

## 같은 품번의 리오더

차수 번호는 **프로젝트 + 품번 + 컬러**별로 누적합니다. 예를 들어 프로젝트 A의 1·2차와 프로젝트 B의 1차는 서로 다른 생산 기록입니다. 파일 수량이 이전과 같아도 다시 적용하면 새 차수가 만들어집니다. 동일 파일의 의도하지 않은 재적용은 피하고, 이미 생성된 차수 수정은 해당 상세 화면에서 처리하세요.

업로드 요청 자체의 재시도는 요청 식별자로 중복 생성을 막습니다. 파일을 새로 선택해 적용하는 작업은 별도의 리오더 요청입니다. 기존 CSV의 ‘교체/추가’는 이전 컬러 합계 화면에 적용하는 방식이며, 이전에 만든 생산 차수의 수량·단가·입고 내역은 변경하지 않습니다.

프로젝트·품번·진행 상태 필터에서 여러 항목을 함께 선택할 수 있습니다. 스타일 기본 정보의 현재 프로젝트를 변경해도 과거 생산 차수에 기록한 프로젝트가 이동하지 않습니다.

## 차수 단가, 실제 입고, 마감

**생산 차수·마감**에서 프로젝트·차수별 단가와 품목을 본사 관리자 또는 직원이 입력합니다. 실제 입고는 관리자가 해당 차수에 날짜·사이즈별 수량을 입력합니다. 차수의 오더 수량을 넘는 입고는 허용하지 않습니다. 과거 컬러 합계의 입고 수량은 자동 복사하지 않으므로 기존 자료를 이중 등록하지 않도록 확인하세요.

다음 프로젝트 때문에 스타일의 담당 공장을 바꾸어도 본사는 이전 업체가 이미 동의·생산 시작한 차수의 입고와 마감을 원래 공장 기준으로 마칠 수 있습니다. 공장 계정의 현재 스타일 접근 제한은 유지하며 새 공장이 과거 업체의 생산 동의를 대신 제출할 수 없습니다.

입고에 사용한 단가는 입고 기록에 보존합니다. 입고가 생긴 차수의 단가를 바꾸어 과거 입고를 재계산할 수 없습니다. 다른 단가의 재생산은 새 차수로 등록합니다. 잘못 입력한 입고는 마감 전 관리자가 사유를 남기고 무효 처리한 뒤 바로잡습니다.

**마감 확정**은 당시 프로젝트, 업체·담당자·품번, 단가, PO, 오더·입고 수량, 부가세 제외 금액·부가세·합계와 입고 원본을 보존하고 차수를 잠급니다. 확정 후 수정·삭제하지 않습니다. 정정이 필요하면 기존 확정 차수를 참조하는 새 정정 차수를 작성합니다. 이 기능이 은행 이체나 세금계산서 발행을 실행하지는 않습니다.

을지는 **확정한 생산 차수의 값**으로 다운로드합니다. 대시보드의 프로젝트 필터를 선택하면 해당 프로젝트의 차수만 포함합니다. 공장·담당자·시즌 필터도 해당 차수에 기록한 업체·담당자·프로젝트 기준으로 적용합니다. 다른 프로젝트의 차수가 섞이거나 미확정 차수 때문에 선택한 프로젝트의 다운로드가 막히지 않습니다. 전체 프로젝트를 선택한 경우에는 선택한 품번의 프로젝트 전체를 대상으로 합니다. 이후 스타일 단가나 담당자가 바뀌어도 과거 금액을 다시 계산하지 않습니다. 전체 다운로드에 미확정 차수가 있으면 안내하며, 필요한 확정 차수는 상세에서 개별 다운로드할 수 있습니다. 차수 관리 전 기존 컬러는 이전 을지 방식을 유지합니다. 중화라벨·비와이 자수·품질검사 다운로드는 기존 별도 항목을 유지합니다.

## 이번 실행 범위

앱·SQL·로컬 데이터베이스 정책 및 브라우저 검증은 저장소에서 수행합니다. 사용자 요청에 따라 **실제 Supabase 관리자·본사·두 공장 계정 시험, 운영 백업 실행, 별도 프로젝트에 실제 복원하는 작업은 보류**합니다. 자동 백업·복원 도구의 설정과 사용법은 [백업·복원 가이드](backup-restore.md)에 있습니다. 설정을 하지 않은 상태에서 자동 백업이 작동한다고 간주하지 않습니다.
