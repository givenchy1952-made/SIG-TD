# 부분 납기 · 파샬 입고의 사이즈별 예정 수량

생산 차수의 오더 수량은 그대로 두고, 각 부분 납기일에 들어올 **XXS·XS·S·M·L·XL 예정 수량**을 나누어 기록합니다. 이 계획을 저장해도 생산 차수나 실제 입고 기록이 추가되지 않습니다.

## 입력 방법

1. **스타일 상세 → 생산 조건 협의·승인**에서 M열의 **프로젝트 명칭**과 해당 생산 차수를 선택합니다.
2. **부분 납기 · 파샬 입고 계획 → 부분 납기 등록**을 누릅니다. 새 계획의 첫 차수에는 현재 오더의 사이즈별 수량이 표시됩니다.
3. 1차 납기일과 XXS~XL 예정 수량을 입력하고 **납기 차수 추가**로 2차 이후의 납기일·사이즈별 수량을 입력합니다.
4. 아래 **전체 오더**와 **계획 합계**를 비교합니다. 각 차수 합계는 자동 계산되며, 모든 차수를 더한 수량이 **각 사이즈별로** 오더와 일치해야 합니다. 전체 합계만 같고 XS·XL 등의 배분이 다르면 저장할 수 없습니다.
5. 등록·변경 사유를 입력하고 **부분 납기 저장**을 누릅니다. 이미 PO를 발송한 경우에는 변경 내용을 업체에 별도로 전달·확인할 필요가 있다는 항목도 확인합니다.

각 사이즈는 0 이상의 정수이며, 해당 납기에 예정된 수량이 없으면 `0`을 입력합니다. 한 차수 전체의 예정 수량은 1장 이상이어야 합니다. 납기일은 차수 순서대로 입력하고 최대 24차까지 기록합니다.

PC와 모바일 모두 같은 여섯 사이즈를 사용합니다. 모바일에서는 수량표 안을 좌우로 이동해 모든 열을 확인합니다. 본사·관리자만 계획을 저장하며, 배정 업체는 같은 프로젝트 명칭과 자신의 스타일 계획을 조회합니다.

## 기존 총수량 계획

이전에 차수별 총수량만 저장한 계획은 그대로 보존합니다. 기록하지 않았던 사이즈를 추정하거나 비율로 나누지 않으며, 사이즈 칸은 `—`와 **사이즈별 수량 미등록**으로 표시합니다.

실제 배분을 알고 있는 담당자가 **부분 납기 수정 → 1차 사이즈별 수량 입력**을 눌러 직접 입력합니다. 2차 이후도 같은 방식으로 보완한 뒤 모든 사이즈 합계를 맞추어 저장합니다. 모든 차수를 보완하기 전에는 총수량 형식과 사이즈 형식을 섞어 저장하지 않습니다. 기존 납기일·비고·차수 식별자는 그대로 유지합니다.

업체 회신·생산 시작·실제 입고·마감 이후에는 기존 계획을 직접 수정하지 않습니다. 발송된 PO 원본·업체 회신·본사 승인·실제 입고·마감 금액은 계획 화면의 저장으로 변경하지 않습니다. 다른 사용자가 먼저 저장하거나 오더가 변경된 경우에는 작성값을 유지하고 오래된 저장을 차단합니다.

## SQL 적용

공유 환경의 사이즈별 저장에는 신규 [018_partial_delivery_sizes.sql](../supabase/migrations/018_partial_delivery_sizes.sql)이 필요합니다. 기존 016의 저장 구조를 확장하며 **기존 001~016 파일을 수정하거나 다시 실행하지 않습니다.** 원부자재 컨펌용 017과는 별개의 기능입니다.

016까지 적용되어 있는 프로젝트에서는 Supabase SQL Editor에서 **018 파일 전체만** 검토하여 실행한 뒤 앱을 새로고침합니다. 016이 미적용된 프로젝트는 먼저 기존 부분 납기 기능의 적용 상태를 확인합니다. 운영 데이터에 초기화·예시 시드 SQL을 실행하지 않습니다.

018은 기존 계획·이력을 일괄 변환하거나 새로운 생산·입고 행을 만들지 않습니다. 설치 전에도 기존 총수량 계획은 조회할 수 있으며, 신규 사이즈별 저장에는 추가 설정 안내를 표시합니다. 이 개발 작업에서는 운영 SQL을 자동 실행하지 않았습니다.

## 검증 범위

관련 단위·로컬 PostgreSQL 시험은 여섯 사이즈의 정확한 합계, 총수량만 같은 잘못된 사이즈 배분, 누락·음수·소수·초과 수량, 기존 총수량 계획 보존, 버전 충돌, 본사·업체 권한, 재배정, 회신·입고·마감 이후 수정 차단, SQL 재실행 보존을 확인합니다. 브라우저 검증 결과는 [테스트 결과](TEST_RESULTS.md)에 최종 기록합니다.
