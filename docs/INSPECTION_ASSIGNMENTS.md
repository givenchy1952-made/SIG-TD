# 품질 검사 업체 지정과 기준 단가

에이블과 KOTITI를 일반 생산 공장과 구분하고, 본사가 지정한 스타일·컬러의 검사 오더만 제공한다. 업체 이름을 보고 자동 분류하거나 기존 업체·스타일을 복제하지 않는다.

## 관리자 최초 설정

1. `사용자 · 기본 설정 → 공장 관리`에서 기존 업체가 있는지 먼저 확인한다. 없으면 `공장 추가`로 기본 정보를 저장한다.
2. 저장된 업체의 `업체 서비스 설정`을 열고 서비스 구분을 `품질 검사`로 선택한다.
3. 검사 업체 연결을 `에이블` 또는 `KOTITI`로 지정하고 변경 사유를 입력해 별도로 저장한다. 같은 검사 업체를 두 업체 ID에 중복 연결할 수 없다.
4. 해당 외부 계정의 담당 공장을 위 업체로 배정하고 업무 접근 승인·활성 상태를 확인한다.

기본 공장 정보 저장과 서비스 설정 저장은 별개다. 신규 업체 등록이 실패했는데 서비스 설정만 저장되거나, 이름·국가 수정으로 검사 구분이 초기화되지 않는다. `품질 검사 + 미연결`인 계정도 검사 전용 계정이며 조회 가능한 오더는 없다.

## 본사의 오더 지정

1. 스타일 상세의 `가공·품질 관리 → 품질 검사`에서 컬러와 검사 품목·수량·요청 내용을 확인한다.
2. `검사 업체 지정`에서 `미지정 / 에이블 / KOTITI`를 선택한다.
3. 변경 사유를 입력하고 `검사 업체 지정 저장`을 누른다. 지정은 스타일·컬러별이며 생산 차수나 기존 생산 기록을 바꾸지 않는다.

미지정이면 어느 검사 업체도 해당 오더를 조회하지 못한다. 업체를 변경하거나 미지정으로 되돌리면 다음 데이터 조회에서 기존 업체의 목록에서 제거된다. 동시 편집은 버전으로 검사하며, 충돌하면 입력을 보존하고 최신 지정을 확인하도록 안내한다. 기존 지정·변경 사유는 이력에 보존된다.

## 검사 업체 화면

승인된 검사 업체 계정은 일반 생산 메뉴 대신 `품질 검사 오더` 화면을 사용한다. 현재 업체에 지정된 오더만 조회·검색하며 주요 항목은 다음과 같다.

- 프로젝트 명칭(M열), 품번, 컬러, 총 수량
- 사이즈별 오더 수량, 시즌, 본사 요청 납기, 검사 품목·요청 수량·상태·메모
- 자기 업체의 검사 품목별 기준 단가

프로젝트 예산 관리 코드(A열), 원본 오더 파일, 일반 스타일 상세, 생산 PO, 다른 업체의 오더·기준 단가, 본사 내부 금액은 제공하지 않는다. 직접 URL을 입력해도 일반 업무 화면으로 전환되지 않는다. 클라우드에서는 최소 오더 조회 RPC와 RLS로 범위를 제한하며, 일반 생산 테이블을 먼저 불러온 다음 숨기는 방식에 의존하지 않는다.

검사 전용 화면의 새로고침은 편집 중에는 비활성화된다. 데이터 저장 뒤 화면 갱신이 실패하면 재저장을 유도하지 않고 최신 화면을 다시 불러오도록 안내한다.

## 검사 기준 단가와 오더 단가

검사 업체 또는 본사는 품목별 `검사 기준 단가 등록/수정`에서 단가와 변경 사유를 저장한다. 빈칸(미입력)과 0원은 구분하며 소수 둘째 자리까지 입력할 수 있다. 이 값은 이후 오더를 위한 기준이며 이미 저장된 오더의 금액을 자동으로 바꾸지 않는다.

본사는 지정 업체·검사 품목과 기준 단가를 확인한 뒤 `이 오더에 기준 단가 적용`을 명시적으로 실행한다. 적용 시 현재 검사 업체 지정 버전과 오더 단가 버전을 확인한다. 같은 업체의 기존 저장 단가는 유지하며, 업체 변경에 따른 새 단가는 기존 이력을 남겨 적용한다. 확정된 마감 금액을 기준 단가 변경으로 덮어쓰지 않는다.

## 데이터베이스 적용

기존 001~019 마이그레이션이 적용된 환경에서 다음 새 파일을 순서대로 검토·수동 실행한다.

1. `supabase/migrations/020_inspection_assignments.sql`
2. `supabase/migrations/021_supplier_work_rates.sql`

020은 업체 서비스 구분·검사 업체 지정·이력과 최소 조회 및 접근 제한을 추가한다. 021은 업체별 공통 작업·품목 기준 단가와 오더 단가 적용을 추가한다. 두 파일 모두 운영 업체를 자동 생성하거나 기존 업체를 이름으로 추측해 분류하지 않는다. 운영 SQL은 이 개발 작업에서 자동 실행하지 않는다.

020 미적용 시 검사 업체 지정·서비스 설정을 준비 중으로 표시하고 저장을 막는다. 검사 계정으로 이미 분류된 경우 조회 실패나 업체 미연결을 이유로 생산 화면 접근을 허용하지 않는다. 021 미적용 시 검사 오더 접근 제어는 유지하며 기준 단가 저장은 비활성화한다.

## 확인할 자동 검증

- `tests/inspection-access.e2e.spec.ts`: PC·모바일 지정 전 비공개, HQ 지정, 업체 간 오더·기준 단가 분리, 지정 변경·해제, 최소 정보, 직접 URL 접근, 기준 단가 명시 적용, 설정 미적용 및 업체 서비스 설정 유지
- `tests/inspection-assignments.test.ts`: 최소 정보 투영·계정 범위·지정 변경·버전 보호
- `tests/inspection-assignments-cloud.test.ts`, `tests/inspection-cloud-workspace.test.ts`: 클라우드 capability·최소 조회·일반 업무 조회 제외
- `tests/inspection-assignments-database.test.ts`: SQL020 기반 RLS·RPC·수정 권한·정보 범위
- 공급사 단가 관련 테스트: SQL021 및 공통 단가 저장·명시 적용·기존 금액 보존

브라우저 테스트는 체험 저장소의 명시적 QA 업체를 사용하며 실제 수신자에게 메일을 보내거나 운영 데이터를 변경하지 않는다. 실제 실행 결과는 작업 완료 보고의 검증 결과를 기준으로 한다.
