# SIG-TD 실사용 전 인수 및 배포 체크리스트

이 문서는 기존 기능을 다시 구현하는 대신 **실제 운영 가능 여부를 확인**하기 위한 검증표입니다. 자동 테스트 통과만으로 운영 승인을 내리지 않습니다. 상세 설정은 [README](../README.md), [추가 업무 설정](OPERATIONS_SETUP.md), [테스트 결과](TEST_RESULTS.md)를 참고하세요.

## 1. 배포 전 필수 확인 (GO / NO-GO)

| 구분 | 확인 방법 | 통과 기준 |
| --- | --- | --- |
| 소스·빌드 | PR의 `SIG-TD quality checks` 결과 확인 | 빌드, 도메인·DB·PO 테스트, 브라우저 회귀 테스트 모두 통과 |
| 운영 DB | Supabase SQL Editor에서 적용된 migration 버전 기록 | 신규: 001→002→003→004, 기존: 미적용 증분만 적용; 재실행·초기화 없음 |
| 로그인 | 고정 배포 도메인에서 가입·인증·로그인·비밀번호 재설정 | 인증 링크가 localhost로 돌아가지 않고 정상 복귀 |
| 권한 | 관리자·본사·A공장·B공장·미승인 계정으로 별도 브라우저 로그인 | 공장 간 데이터·파일·휴가·단가 노출 없음; 승인 전 업무 접근 차단 |
| 실시간 협업 | 관리자와 본사가 같은 스타일을 동시에 편집 | 변경 반영 및 오래된 버전 저장 거부; 편집 중인 내용 유실 없음 |
| 첨부파일 | 테스트용 PNG·PDF 업로드/다운로드, 타 공장 접근 시도 | 허용된 계정만 원본 다운로드; 10MB 초과·금지 형식 차단 |

| 부분 출고 | 같은 컬러의 1차·2차 출고와 관리자 무효 처리 | 사이즈별 누계·실 출고일·이력 일치, 기존 기준 수량 보존 |
| 오더 업로드 | 실제 양식의 복사본으로 CSV/Excel 미리보기·적용 | 품번·컬러·6사이즈·총수량 대조, 미등록 품번/중복/오류 행은 전체 취소 |
| 라벨·자수 | 중화 라벨·비와이 자수 작업 1건씩 입력 | 종류·요청/발주·로스·완료 수량·일자 및 권한 일치 |
| 일정 | 개인 비공개·본사 공유·런칭·업체 휴가 등록 | 역할별 공개 범위, 삭제·변경 이력 일치 |
| 을지 | 프로젝트 코드·장당 원가·실입고 입력 후 다운로드 | 원본 표·수식·인쇄 설정 유지, T=원가×실입고, 미입력 시 차단 |
| 중국 지사 | 중국 현지 네트워크/기기에서 고정 운영 주소 접속 | 로그인·이미지·업무 저장·첨부 다운로드까지 실제 사용 가능 |
| 백업·복구 | 운영 책임자가 복구 시나리오와 접근 권한 확인 | DB·Storage 복구 책임자/절차/주기 문서화 및 복구 연습 완료 |

**NO-GO:** 한 항목이라도 필수 검증에 실패하면 실사용 데이터를 투입하거나 외부 공장에 운영 주소를 배포하지 않습니다. 문제를 수정하고 해당 항목을 재검증합니다.

## 2. 검증 순서와 기록

1. 실제 회사 데이터를 사용하지 않는 별도 테스트 환경에서 DB 백업·복구 정책과 접근 권한을 먼저 확인합니다. **이미 적용된 SQL을 다시 실행하지 않습니다.**
2. 관리자·본사·서로 다른 공장 2곳·미승인 계정으로 테스트합니다. 체험 모드의 역할 변경은 실제 RLS 검증을 대신하지 못합니다.
3. 하나의 테스트 스타일을 **샘플 → PO → 오더 → 생산 → 부분 출고 → 입고 → 을지 마감** 순서로 진행하고, 단계마다 작성자·시간·수량·변경 사유를 기록합니다.
4. 같은 테스트 스타일에서 동시 편집, 접근 거부, 파일 다운로드, 오류·중복 발송 방지 시나리오를 확인합니다.
5. 중국 현지 사용자가 PC와 휴대전화로 접속하여 네트워크 접근성을 직접 검증합니다. 한국에서의 접속 성공만으로 중국 사용 가능을 판단하지 않습니다.
6. 운영 책임자와 생산 실무 담당자가 각각 승인한 후 소수 사용자에게 먼저 배포합니다. 초기 운영 기간에는 기존 Excel을 대조 자료로 유지합니다.

## 3. 배포 및 보안 원칙

- GitHub 저장소가 공개 상태이므로 고객·공장·직원 정보, 실제 발주 CSV, 개인 자료, 토큰·비밀번호·Resend API 키를 커밋하지 않습니다.
- 브라우저의 `VITE_*` 환경변수에는 공개 가능한 Supabase URL·anon/publishable 키만 사용합니다. `service_role`, `RESEND_API_KEY`, `PO_FROM_EMAIL`, `PO_ALLOWED_ORIGINS` 등 서버 설정은 각 서비스의 서버 전용 Secrets에서 관리합니다.
- Edge Function 배포·Supabase SQL 적용·Vercel 환경변수 수정은 CI에서 자동으로 수행하지 않습니다. 담당자가 백업과 변경 내용을 확인한 뒤 별도로 적용합니다.
- 문제가 발생하면 먼저 **추가 쓰기와 PO 발송을 중단**하고 오류 시각·영향 범위·버전을 기록합니다. UI 버전은 검증된 이전 배포로 되돌릴 수 있지만, DB migration을 임의로 역실행하지 않습니다. 데이터 복구는 사전에 검증한 백업 절차를 따릅니다.
- `sent`는 이메일 공급자의 **발송 요청 접수**를 뜻하며 수신 성공을 의미하지 않습니다. 공급자 기록으로 실제 결과를 확인합니다.
- CI는 브라우저 체험 모드와 로컬 테스트 PostgreSQL을 사용합니다. 운영 Supabase·Resend·중국 네트워크의 성공 여부는 검증하지 않습니다.
