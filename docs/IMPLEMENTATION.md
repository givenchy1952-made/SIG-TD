## 권한 해석

요청서에는 실제 출고·입고 수량과 날짜에 대한 문장이 일부 겹칩니다. 1차 구현은 처음 제시한 수량 원칙을 적용합니다.

- 관리자는 업무 항목을 관리합니다. 다른 사람의 비공개 개인 휴가는 조회할 수 없습니다.
- 출고 **수량**은 외부 공장과 관리자만 입력합니다. 본사 직원은 다운로드·조회할 수 있습니다.
- 입고 **수량**은 관리자만 입력합니다.
- 실제 출고일·실제 입고일·세금계산서 상태는 해당 스타일에 접근 가능한 관리자·본사·공장 모두 입력할 수 있습니다.
- 공장은 메인 컨펌 예정일, 사이즈 측정, 공장 코멘트와 샘플 제작·발송 진행을 입력할 수 있습니다.
- 공장은 공장 배정, 스타일 기준 정보, 본사 요청, 기준 납기, PP 승인, 최종 컨펌과 본사 체크리스트를 수정할 수 없습니다.
- 담당자는 실제 가입 계정의 승인·활성 상태로 관리합니다. 담당자 제거는 비활성화이며 기존 사용자·업무·감사 기록은 남깁니다.
- 본사 직원의 복수 담당 공장 배정은 업무 담당 구분이며 본사 전체 스타일 조회 권한을 축소하지 않습니다. 외부 공장 소속 배정과 별개의 데이터입니다.
- 을지 단가·프로젝트 코드·품목 구분·전용 변경 이력과 SIG 을지 자동 작성은 본사·관리자만 사용합니다. 공장용 일반 감사 이력에는 단가·코드 값을 넣지 않습니다.
- 공장은 본인 비공개 개인 휴가만 등록합니다. 제품 런칭은 승인된 계정 전체 조회, 협력업체 휴가는 본사 조회·관리이며 공장에는 알림·이력도 보이지 않습니다.

화면에서 비활성화한 입력뿐 아니라 SQL RPC에서도 같은 경계를 검사합니다. 공장 계정의 새 샘플 차수·생산 컬러 추가와 기존 이력 삭제는 허용하지 않습니다.

## 저장과 충돌 처리

스타일 하나를 원자적인 저장 단위로 관리합니다. 각 스타일에는 버전 번호가 있습니다. 같은 스타일을 두 명이 열고 먼저 한 명이 저장했다면 두 번째 저장은 버전 충돌로 실패합니다. 이 경우 자동으로 합치거나 덮어쓰지 않습니다. 다른 컬러·샘플 차수를 수정한 경우에도 같은 스타일이면 충돌할 수 있으며, 안전을 위해 최신 내용을 확인한 뒤 다시 반영해야 합니다.

저장 시 변경 사유를 기록하며 일정 변경의 이전 날짜·변경 날짜는 감사 이력의 이전/이후 값에 남습니다. 샘플·생산 차수는 누적됩니다. 관리자 삭제는 보존 삭제로, 일반 업무 목록에서 제외하되 관련 기록을 유지합니다.

003 추가 업무는 PO·출고 차수·라벨·자수·개별 일정·공장 배정의 버전과 사유를 별도로 관리합니다. 004는 스타일·컬러별 을지 정산 기준을 별도 버전으로 저장하고 단가의 이전/이후 값·사유를 본사 전용 감사 테이블에 보존합니다. 005는 프로젝트 코드·명칭을 분리하고 스타일·프로젝트 확인 등록, 개인 반차·반반차, 컬러별 품질 검사·상의/하의 치수표와 해당 버전·변경 이력을 추가합니다. 오더 파일 적용은 모든 대상 스타일의 버전을 한 번에 확인하는 트랜잭션입니다. 개인 일정은 전용 감사 테이블을 사용하고 현재·과거 공개 범위를 모두 적용해 비공개 내용이 전역 이력에 노출되지 않게 합니다.

프로필·공장·프로젝트와 코멘트·첨부파일은 별도 데이터입니다. 스타일 편집의 버전 충돌 보호와 메타데이터 편집의 동작은 구분됩니다. 코멘트·파일은 추가 중심으로 관리하고 기존 업무 이력을 덮어쓰지 않습니다.

## 체험 모드와 실제 협업의 차이

| 구분 | 체험 모드 | Supabase 연결 모드 |
| --- | --- | --- |
| 목적 | 전체 기능과 역할별 화면 확인 | 실제 계정·공장별 협업 |
| 업무 저장 | 브라우저 localStorage | Supabase Postgres |
| 파일 저장 | 브라우저 IndexedDB | 비공개 Supabase Storage |
| 사용자 | 예시 역할 선택 | Auth 로그인 + 관리자가 승인한 프로필 |
| 공유 | 같은 브라우저의 탭 | 같은 Supabase 프로젝트의 허용된 사용자 |
| 권한 경계 | 체험용 클라이언트 검사 | RLS·RPC·Storage 정책에서 강제 |
| 데이터 복구 | 브라우저 저장소 삭제 시 유실 | 프로젝트 백업·보존 설정에 따름 |

브라우저 체험 모드에는 예시 데이터 표시가 있으며 실생산 기록으로 취급하지 않습니다. 실제 모드로 바꿀 때 브라우저 예시를 자동으로 업로드하지 않습니다. 운영 서버 연결 실패 시 체험 모드로 자동 전환해 성공한 것처럼 표시하지 않습니다.

## 첨부파일

JPG·PNG·WEBP·PDF, 파일당 10MB 이내입니다. 클라우드에서는 `sig-files` 비공개 버킷과 스타일 ID 기반 경로를 사용합니다. 스타일 접근 권한을 가진 승인된 활성 계정만 파일을 추가·다운로드할 수 있습니다. 다른 공장의 파일 경로를 알아도 정책에서 접근을 차단합니다. 화면의 허용 형식·용량 검사와 저장소의 제한을 함께 사용합니다.

파일 자동 악성코드 검사, 바이러스 스캔 파이프라인, 대용량 동영상, 전자서명은 포함하지 않습니다.

## 대표 이미지 운영 방법

스타일 상세의 **대표 이미지 → 스타일 기본 또는 컬러 선택 → 파일 선택 → 변경 사유 → 저장** 순서로 등록합니다. 관리자와 본사 직원만 이미지 업로드·교체·연결 해제를 할 수 있습니다. 외부 공장은 자신에게 배정된 스타일의 이미지를 조회할 수 있습니다.

스타일 기본 이미지를 공통으로 사용하고 필요할 때 컬러별 이미지를 추가합니다. 컬러에 별도 이미지가 있으면 이를 우선 표시하며, 없거나 연결을 해제하면 스타일 기본 이미지를 표시합니다. 이미지가 전혀 없으면 아이콘을 표시합니다. 대표 이미지 변경은 업무 첨부파일의 추가 기능과 구분됩니다.

JPG·PNG·WEBP, 파일당 10MB 이내를 허용합니다. 투명 컷아웃은 사용자가 배경을 제거한 PNG로 준비해야 하며 자동 배경 제거는 제공하지 않습니다. 이미지는 잘라내지 않는 `contain` 방식으로 원본 비율을 유지하고, 투명 부분은 화면의 체크무늬 배경 위에 표시합니다.

실제 모드에서는 기존 비공개 `sig-files` 버킷과 사용자별 파일 접근 정책을 사용합니다. 인증된 파일을 Blob URL로 표시하며 공개 버킷·영구 공개 URL은 사용하지 않습니다. 교체·연결 해제된 파일은 과거 이력을 보존하기 위해 삭제하지 않습니다. 체험 모드는 이미지 파일을 IndexedDB, 연결 정보를 localStorage에 저장하므로 같은 브라우저 내 확인용입니다. 실제 사용자 간 공유는 Supabase 연결이 필요합니다.

### 대표 이미지 마이그레이션

- **새 프로젝트:** `001_initial.sql` 적용 후 `002_style_images.sql`을 각각 한 번 적용합니다.
- **001 적용이 끝난 기존 프로젝트:** `002_style_images.sql`만 한 번 적용합니다. **001은 재실행하지 않습니다.**
- 실제 공유 서비스는 002 적용 뒤 새 앱 버전을 재배포해야 합니다. 클라이언트 환경변수를 바꿨다면 다시 빌드합니다.
- 002가 없는 기존 프로젝트에서도 업무 화면 전체 로딩을 막지 않고 이미지 없는 항목에 아이콘을 표시합니다. 스타일 상세의 설정 안내에 따라 SQL을 적용하고 다시 불러오세요.

## 추가 업무 마이그레이션과 사용법

새 프로젝트는 `001 → 002 → 003 → 004 → 005` 순서로 각 SQL을 한 번 적용합니다. **001~004가 적용된 기존 프로젝트는 `005_workflow_refinements.sql`만 한 번 적용하며, 이미 적용한 SQL을 재실행하지 않습니다.** 빠진 마이그레이션이 있으면 그 번호부터 순서대로 적용합니다. 005는 프로젝트 코드·명칭 분리와 확인 등록, 반차·반반차, 품질 검사·치수표 저장을 추가하며 기존 업무를 초기화하지 않습니다. 005가 없으면 이 신규 저장 기능만 안내와 함께 비활성화하고 기존 003·004 업무는 유지합니다. 적용 후 최신 앱을 다시 배포합니다.

PO 실제 메일 발송에는 별도로 Supabase Edge Function과 Resend 서버 자격정보·검증된 발신 주소·허용 origin 설정이 필요합니다. 초안 저장 또는 `.eml` 생성은 실제 발송이 아닙니다. 선택한 스타일 PDF·이미지 1개(최대 10MB)는 실제 메일에 첨부하며, `.eml`에는 첨부하지 않습니다. 서버가 확인한 메일 서비스 접수만 `sent`로 기록하고 화면에는 **발송 접수**로 표시합니다. 실제 수신·열람은 별도 확인 사항입니다. 결과 불명확 상태에서는 중복 재발송을 막습니다.

SIG ORDER QTY는 **F열만** 품번 기준으로 읽고, 컬러 포함 품번이면 끝 두 자리를 분리합니다. 기본 품번만 있으면 등록된 단일 컬러 또는 사용자가 승인한 B 예산코드의 정확한 A+F+두 자리 일치를 통해 전체 품번을 연결합니다. 화면에는 전체 품번만 확인·수정하며 I열은 읽지 않습니다. 기존 전체 품번 코드도 재사용합니다. 품번 매칭 전에 수량을 읽어 미등록 행에도 실제 파일 수량을 표시하며, 확인 전에는 저장하지 않습니다. 이 보완은 SQL 변경이 없습니다. AQ~AV 6사이즈·AY 총수량과 A/L/M/S/V/W/X/Y 참조 열을 보관하며 A 프로젝트 코드·M 프로젝트 명칭·L 시즌을 실제 프로젝트로 확인 등록·연결할 수 있습니다. 참조 값은 본사 전용 원본 탭에서 편집하며 수기 수량은 메인 생산에서 수정합니다. 원본의 F·수량은 가져온 당시 스냅샷으로 남습니다. 다시 제공된 CSV를 실제로 읽어 CP949·33행·153열, 7행의 실제 머리글, 8행 데이터 한 개의 여섯 사이즈 합계 4,138개를 확인했습니다. UTF-8 우선·CP949 자동 판독으로 재저장 없이 읽으며 상단 사이즈 요약보다 스타일코드·TOTAL QTY 머리글을 우선 인식합니다. 선택 범위 밖 이미지·부자재 오류 문자열은 무시하고 선택 열의 수량 오류·Excel 오류 셀과 CSV의 정확한 Excel 오류 문자열은 차단합니다. 실제 파일 로컬 검증과 운영 DB 반영은 별개이며 실제 업무 CSV는 저장소에 넣지 않습니다.

제공된 SIG_을지.xlsx의 대금지급(을) 원본을 개인 문서 속성·로컬 경로를 정리한 기본 양식으로 포함합니다. 스타일 상세 **을지·단가**에서 저장한 프로젝트 코드·원가·품목 구분과 현재 업무의 실제 입고·오더·공장·담당자 값을 연결해 **스타일 상세 상단 → 을지 다운로드** 또는 본사 대시보드의 **을지 양식 다운로드 → SIG 을지 자동 작성**에서 다운로드합니다. A/C/D/I/N/O/P/Q/R/S/T/W를 지정대로 채우며 O=1, Q=P, 원단 YDS·제품/라벨 EA입니다. 사용자가 확인한 T=N×R 부가세 제외 금액, 원본 U=10%·V=합계 수식과 표·인쇄 설정을 유지하고 데이터 행·합계 범위를 확장합니다. 원가·프로젝트 코드·입고일 등 필수 값이 없으면 대상 전체의 다운로드를 막습니다. 원가는 생산 진행마다 본사 관리자·팀원이 현재 스타일·컬러·프로젝트 기준으로 직접 입력·수정하고 이전 값은 전용 이력에 보존합니다. CSV·다른 생산의 단가를 자동 복사하지 않습니다. 이 설명은 기존 컬러 합계 방식이며, 새 생산 건은 007~009의 프로젝트·차수별 원장과 확정 마감 스냅샷을 사용합니다. 원가 null과 명시적 0원을 구분하고 기존 마감 금액 역산·오더의 실입고 대체를 하지 않습니다.

**다른 양식 · 직접 열 연결**은 기존 사용자 업로드 기능입니다. 이 모드에서는 지정 데이터 영역·연결 열만 수정하고 병합·수식·행 부족 등 지원하지 않는 구조는 중단합니다. ExcelJS가 지원하지 않는 특수 개체까지 완전 보존한다고 보장하지 않으며 SIG 고정 원본 자동 작성과 구분합니다.

PO 독립 탭, 메인 생산의 통합 출고 수량표, 가공·품질 관리, 상의·하의 치수표와 반차·반반차를 포함한 기능별 화면 위치, 실제 파일 가져오기·양식 채우기, PO 함수 배포·서버 Secrets 설정은 [OPERATIONS_SETUP.md](OPERATIONS_SETUP.md)에 설명합니다.

### 005 화면과 입력 규칙

스타일 상세는 **PO**를 독립 탭으로 분리합니다. 출고 차수는 **메인 생산 → 사이즈별 수량**에서 오더·실 출고 합계·실 입고와 함께 표시하고, 기존 입력 기준과 유효한 N차 출고를 더합니다. 패킹리스트 수량 행만 숨기며 기존 수량과 패킹리스트 확인 체크는 보존합니다. **가공·품질 관리**에는 중화 라벨·비와이 자수·품질 검사를 묶고 검사 대상은 아우터·니트·티셔츠·바지·가방·악세사리·모자로 고정합니다. 품질 검사는 본사가 작성하고 공장은 배정 스타일을 조회합니다.

상의·하의 측정표는 위치·편차·XXS~XXL 7사이즈, cm·소수 둘째 자리, 빈칸 null과 입력 0을 구분합니다. 본사와 배정 공장이 측정표를 저장할 수 있지만 공장은 품질 검사 값을 바꾸지 않습니다. 이전 서술 기록은 읽기 전용 보관이며 예시 치수를 실제 값으로 자동 채우지 않습니다.

개인 반차·반반차는 당일 일정이고, 2시간 반반차는 사용자가 지정한 시작 시각부터 정확히 120분 뒤를 종료로 표시합니다. 회사 근무 시간을 임의 설정하지 않으며 기존 개인·본사·공장 공개 범위와 이력 접근 제한을 유지합니다.

SIG의 미등록 스타일은 공장·본사 담당자·직접 선택한 납기일을 확인한 뒤 기본 정보를 등록합니다. W/Y 이름의 정확한 등록 매칭을 이용하고 없으면 등록된 대상 중 선택하며 공장·계정을 임의 생성하지 않습니다. S 발주 요청일을 납기로 대신 쓰지 않습니다. 신규 스타일명은 우선 F에서 분리한 기본 품번으로 두고 수량·실출고·실입고는 기본값 0으로 시작합니다. 이후 별도로 **검증된 오더 적용**을 눌러 AQ~AV 오더 수량을 반영합니다. 기존 품번은 **프로젝트 연결**에서 A/M 변경 대상을 확인하며, 프로젝트 변경은 해당 스타일의 모든 컬러에 적용됩니다.

## 현재 버전의 제한

- 외부 서비스 계정·키가 제공되지 않아 실제 Supabase 원격 연결 및 Vercel 배포는 완료한 것으로 간주하지 않습니다.
- 재접속 후 다시 읽기는 가능하지만 오프라인 쓰기 대기열과 자동 재전송은 없습니다.
- 일정 알림은 화면의 지연·다가오는 일정 안내입니다. 일정 알림용 이메일·카카오·푸시·SMS는 없습니다. PO 메일 발송은 별도 서버 함수와 실제 서비스 설정이 필요한 기능입니다.
- 기존 업체 마감 금액은 원화 기준 수기 입력입니다. SIG 을지의 T·U·V는 저장한 장당 원가와 실제 입고 수량으로 계산합니다. 세금계산서 실제 발행 API, 회계 ERP 연동, 송금·통화 환산·지급 실행은 포함하지 않습니다.
- 사이즈 측정은 상의·하의의 위치·편차·XXS~XXL 표로 저장합니다. 기존 자유 형식 기록은 보관하며, 공차 자동 판정은 포함하지 않습니다.
- 수량 일괄 적용은 등록된 품번·컬러를 대상으로 합니다. SIG는 별도의 확인 등록 단계에서 미등록 스타일·컬러·A/M 프로젝트를 먼저 저장할 수 있습니다. 프로젝트·스타일 한 건의 등록과 뒤의 수량 적용은 별도 트랜잭션입니다. 기존 HTML 전체 이관과 임의 ERP 데이터 자동 변환은 포함하지 않습니다.
- 제공된 을지 파일 생성과 CSV 로컬 대조는 실제 운영 DB 적용·지급 업무 인수와 구분합니다. 원격 Resend·Supabase 함수 설정이 완료되지 않은 항목은 검증 완료로 간주하지 않습니다.
- 업무 전용 초대 이메일과 관리자에 의한 Auth 계정 생성은 구현하지 않습니다. 사용자가 가입한 후 승인합니다.
- 미등록 공장·담당자는 먼저 관리자 메뉴에서 준비해야 합니다. 프로젝트는 관리자 메뉴 또는 SIG의 A/M 확인 등록으로 준비할 수 있으며, 기존 코드의 명칭·시즌 충돌은 자동 변경하지 않습니다.
- 자동화 테스트가 통과해도 현업 데이터·대량 데이터·실제 사용자의 전체 인수 검증을 대신하지 않습니다.

## 운영 전 실제 서비스 확인

새 Supabase 테스트 프로젝트를 사용하고 서로 다른 브라우저 또는 브라우저 프로필에 관리자, 본사, A공장, B공장, 미승인 계정을 준비하세요. 체험 역할 전환으로 다음 검증을 대신하지 마세요.

1. **최초 설정**: 새 프로젝트는 001 → 002 → 003 → 004 → 005를 순서대로 한 번씩 적용합니다. 기존 001~004 적용 프로젝트는 005만 적용하며, 빠진 마이그레이션이 있으면 그 번호부터 순서대로 적용합니다. 이메일 인증과 리다이렉트 설정, 첫 관리자 SQL 등록을 수행합니다. 공장·프로젝트·스타일을 만듭니다.
2. **미승인·비활성 계정**: 업무 데이터와 파일 접근이 모두 차단되는지 확인합니다. 승인 후 접근하고, 비활성화한 뒤 다시 접근을 시도합니다.
3. **공장 격리**: A·B공장에 서로 다른 스타일을 배정합니다. 목록뿐 아니라 직접 API·RPC 및 파일 경로 요청에서도 타 공장 접근이 차단되는지 확인합니다.
4. **필드 권한**: 공장에서 기준 납기·본사 요청·PP 승인·최종 컨펌·입고 수량을 수정하려 할 때 서버에서 실패하는지 확인합니다. 본사 계정의 실 출고·입고 수량 수정도 실패해야 합니다.
5. **실시간 협업**: 같은 스타일을 허용된 두 계정으로 열고 코멘트·생산 수량·상태를 저장해 다른 화면에 반영되는지 확인합니다. WebSocket 연결 상태와 끊김 안내를 확인합니다.
6. **충돌 보호**: 두 사용자가 같은 버전을 편집합니다. 첫 번째 저장 후 두 번째 저장이 거부되고, 두 번째 사용자의 편집 값이 유지되는지 확인합니다. 최신 데이터를 읽고 내용을 다시 적용합니다.
7. **파일**: 허용 파일 업로드·다운로드, 10MB 초과·허용하지 않은 MIME 차단, 타 공장 다운로드 차단을 확인합니다.
8. **대표 이미지**: 본사에서 스타일 기본과 컬러별 투명 PNG를 등록해 공장 계정에 반영되는지 확인합니다. 컬러별 대체 표시, 연결 해제 후 기본 이미지 복귀, 타 공장 접근 차단, 변경 이력·파일 보존, 002 미적용 시 설정 안내를 확인합니다.
9. **일정·이력**: 납기를 사유와 함께 변경하고 이전·변경 날짜 및 수정자가 남는지 확인합니다. 추가 샘플 차수·PP 기록이 누적되는지 확인합니다.
10. **수량·다운로드**: 6사이즈 수량 합계와 실제 출입고 차이, 프로젝트별 합계를 대조합니다. CP949 CSV의 머리글·16열·합계를 확인하고 SIG 을지의 프로젝트 코드·원가·실입고·T=N×R·부가세·합계·표·인쇄를 실제 Excel에서 대조합니다. 단가 전용 이력이 공장에 노출되지 않는지 확인합니다.
11. **계정·삭제**: 신규 가입 승인, 역할 변경, 공장 재배정, 비활성화, 보존 삭제 이력이 남는지 확인합니다. 업무 보존·백업·복원 정책을 검토합니다.
12. **화면**: PC·태블릿·모바일에서 테이블 가로 스크롤, 상세 입력·파일 업로드·캘린더·오류 안내가 사용 가능한지 확인합니다.
13. **배포**: Vercel 배포 도메인에서 로그인·이메일 확인 경로와 모든 환경변수를 검증합니다. 연결 정보 변경 후 재빌드 여부를 확인합니다.

추가 업무의 실제 Excel·PO 메일·부분 출고·고정 목록·캘린더 개인정보 검증은 [추가 업무 확인 항목](OPERATIONS_SETUP.md#실제-서비스-확인-항목)도 수행하세요. 실행 결과, 승인 담당자 및 발견한 문제를 별도 인수 기록에 남긴 후 실제 업무 사용을 결정하세요.


전체 품번 가져오기는 신규 한 건의 등록 정보를 자동으로 준비하고 **품번 등록 및 수량 적용**으로 등록과 수량 적용을 연속 진행합니다. AO 입고예정일이 유효하면 출처와 함께 기준 납기로 표시하고 공장 법인 표기 차이만 정규화합니다. 별도 SQL 변경은 없고 등록·수량 트랜잭션은 분리되어 있어 부분 완료를 정확히 안내합니다. 기존 스타일·원본 기록의 버전은 처음 파일을 읽은 값을 보존합니다.


복수 선택 필터는 null(전체), 빈 선택(없음), 선택 값 집합을 구분합니다. 같은 항목은 OR, 서로 다른 필터는 AND이며 색상·공정 상태는 같은 생산 행에서, 샘플 차수·상태는 같은 샘플에서 함께 검사합니다. 필터 팝업은 검색·전체 선택·해제·Escape 복귀와 화면 밖 잘림 방지를 지원하고 권한에 따라 조회된 항목만 표시합니다.

을지 작성 항목에 label/embroidery/quality를 추가합니다. 메인 제품은 기존 엄격한 필수 검증을 유지하고 가공·검사는 별도 수량·미입력 단가 및 업체 규칙을 사용합니다. 라벨/자수는 스타일 단위, 품질검사는 선택한 생산 행 단위입니다. 다운로드는 DB를 변경하지 않고 가공 업체명을 고정하며 검사 업체명은 빈 셀로 씁니다. 추가 SQL은 없습니다.
