# 구성원 탈퇴

관리자는 **사용자 · 기본 설정 → 전체 구성원 → 구성원 탈퇴**에서 팀원 또는 공장 계정의 업무 접근을 종료할 수 있습니다. 이름·이메일을 확인하고 사유를 입력한 뒤 접근 차단 확인란을 체크해 저장합니다. 현재 로그인한 관리자 본인의 탈퇴는 허용하지 않습니다.

탈퇴 처리된 구성원은 계정 상태에 **탈퇴**로 표시됩니다. 승인과 활성이 해제되므로 다음 로그인뿐 아니라 기존 세션의 데이터·첨부파일 접근도 데이터베이스 권한 검사에서 차단됩니다. 이전에 브라우저에 내려받거나 따로 저장한 파일까지 회수하지는 않습니다.

스타일·PO·입출고·마감·사진·PDF와 원래 담당자 참조는 보존합니다. Auth 계정과 프로필을 삭제하는 기능은 아니며, 탈퇴 사유·처리자·처리 시각을 관리자만 읽을 수 있는 변경 이력으로 남깁니다. 업무를 이어받을 담당자는 스타일의 기본 정보에서 변경할 수 있습니다.

## 운영 프로젝트 적용

1. 기존 001~009 SQL이 적용된 프로젝트에서 [010_member_withdrawal.sql](../supabase/migrations/010_member_withdrawal.sql)의 전체 내용을 실행합니다. [SIG SQL Editor](https://supabase.com/dashboard/project/phmuweuwjyzbziqlpplz/sql/new)에서 실행할 수 있습니다.
2. 새 앱 코드를 배포하고 관리자 계정으로 새로고침합니다. `010_member_withdrawal.sql 적용 후 사용할 수 있습니다` 안내가 사라지면 탈퇴 버튼을 사용할 수 있습니다.
3. 먼저 실제 권한을 회수할 대상의 이름과 이메일을 확인한 뒤 처리합니다. 설정 SQL 자체는 기존 구성원을 탈퇴시키지 않습니다.

010은 재실행해도 구성원·탈퇴 표식·이력을 지우지 않습니다. 이전 001~009 파일을 다시 실행할 필요는 없습니다. 사용자 환경에서의 실제 계정 탈퇴와 외부 Supabase 서비스 테스트는 자동 실행하지 않습니다.

## 복구

관리자는 탈퇴 구성원의 **수정**에서 **업무 접근 승인**과 **활성 계정**을 모두 켜고 저장해 복구합니다. 공장 계정은 등록된 담당 공장도 지정되어 있어야 합니다. 복구하면 현재 탈퇴 표시는 해제되며 과거 탈퇴 이력은 남습니다. 본사 직원은 탈퇴 계정을 수정하거나 복구할 수 없습니다.
