# 가공·품질 단가와 을지 안내

2026-10-29 검증 브랜치의 변경이며, SQL 013과 새 앱을 운영에 적용한 상태는 아닙니다. 운영 적용·자동 배포·실제 업체 대상 시험 메일 발송은 수행하지 않습니다. 생산 조건의 제안·본사 승인 단가는 [생산 조건 협의·승인 가이드](PRODUCTION_CONDITIONS.md)에서 별도로 설명합니다.

## 단가 입력 위치

1. 품번 상세의 **가공·품질 관리** 탭을 엽니다.
2. 상단 **가공·품질 단가**에서 **중화 라벨 / 비와이 자수 / 에이블 품질 검사**를 선택합니다.
3. 전체 품번·컬러와 작업명을 확인하고 해당 행의 **단가 수정**을 누릅니다.
4. 단가와 변경 사유를 입력한 뒤 **단가 저장**을 누릅니다.

본사와 현재 그 스타일에 배정된 승인·활성 업체 계정이 입력할 수 있습니다. 업체의 단가 입력 권한이 본사 작업 지시·검사 정보·제품 원가 수정 권한으로 확대되지는 않습니다. 본사에서 저장한 가공·검사 작업이 먼저 있어야 해당 작업의 단가 행이 표시됩니다.

단가는 **스타일·컬러·작업**별로 저장합니다. 한 작업의 가격을 다른 컬러나 다른 작업에 자동 복사하지 않으며, 직접 수정하기 전까지 다음 조회와 을지 다운로드에도 유지합니다. 라벨·자수는 저장된 작업 행, 품질 검사는 해당 컬러의 검사 대상을 기준으로 구분합니다.

- 금액은 원 단위, 부가세 제외이며 소수 둘째 자리까지 입력합니다.
- 공란은 미입력, `0`은 명시적인 0원입니다. 미입력을 0원으로 바꾸지 않습니다.
- 다른 사용자가 먼저 수정했으면 덮어쓰지 않고 입력값을 유지한 채 충돌을 안내합니다.
- 저장 후 최신 화면을 불러오지 못하면 다시 조회해야 합니다. 편집 중이거나 최신 결과를 확인하지 못한 상태에서 이전 단가로 을지를 내보내지 않도록 보호합니다.

## 가공·품질 을지에 채워지는 값

| 열 | 중화 라벨 | 비와이 자수 | 에이블 품질 검사 |
| --- | --- | --- | --- |
| C · 입고일자 | 메인 생산의 해당 컬러 실입고일 | 동일 | 동일 |
| I · 스타일코드 | 컬러를 포함한 전체 품번 | 동일 | 동일 |
| M · 컬러 | 전체 품번에서 컬러 표시 | 동일 | 동일 |
| N · 단가 | 해당 컬러·작업에 저장한 단가 | 동일 | 해당 컬러·검사 대상에 저장한 단가 |
| P·Q · 오더·발주 수량 | 선택한 컬러의 메인 오더 수량 | 동일 | 동일 |
| R · 정산 기준 수량 | 메인 생산의 해당 컬러 **실출고 수량** | 해당 컬러 **실입고 수량** | 해당 컬러 **실입고 수량** |
| T · 부가세 제외 금액 | 저장 단가 × R | 동일 | 동일 |

C열에는 실제 입력된 메인 실입고일을 사용합니다. 날짜가 없으면 공란으로 남기며, 가공 완료일·예정일·오늘 날짜로 대신 채우지 않습니다. N열도 단가 미등록 시 공란입니다. 제품의 장당 원가를 가공 단가로 대신 사용하지 않습니다. 0원이 저장돼 있으면 N·T에 0원을 반영합니다.

라벨과 자수의 공통 작업은 선택한 컬러별로 행을 작성합니다. 작업 요청·가공 완료·로스 수량 등 기존 작업 내용은 비고에 보존하고, 해당 수량을 R열의 실제 출입고로 간주하지 않습니다. 컬러 필터나 상세에서 선택한 컬러의 범위를 유지하며, 업체명과 품질검사 업체명 공란 처리 등 요청하지 않은 양식 규칙은 유지합니다.

단가·수량으로 계산한 한 행의 금액이 허용 범위를 넘거나 원본 값이 유효하지 않으면 다운로드 전에 오류를 표시합니다. 내용을 임의로 보정하거나 일부 금액을 잘라 저장하지 않습니다.

## 생산 승인 단가와의 구분

이 가이드의 N열 단가는 라벨·자수·품질 검사 작업 대금입니다. 완사입·임가공 생산 발주의 **본사 내부 검토 단가 / 업체 제안 단가 / 본사 최종 승인 단가**와 별도입니다.

생산 차수의 제품 을지와 마감은 본사 최종 승인 단가와 그 차수의 실제 입고를 사용합니다. 가공 단가 저장으로 생산 차수 단가·이미 기록한 입고 원가·확정 마감 스냅샷을 변경하지 않습니다. 가공·품질 을지는 현재 저장 단가와 현재 선택한 컬러의 출입고를 바탕으로 다시 작성하는 파일이므로, 가격을 명시적으로 수정하면 이후 다운로드에 수정한 가격이 반영됩니다.

## 저장·권한과 적용 순서

- [013_processing_unit_prices.sql](../supabase/migrations/013_processing_unit_prices.sql)은 `processing_unit_prices`와 본사 전용 원문 이력 `processing_unit_price_audits`를 추가합니다.
- 가격 저장은 `save_processing_unit_price` RPC를 사용하며, 현재 프로필·공장 배정·실제 작업·컬러·단가 형식·버전·변경 사유를 서버에서 검증합니다. 테이블 직접 수정으로 우회하지 않습니다.
- 업체는 현재 배정된 스타일의 단가를 조회·입력할 수 있습니다. 원문 가격 변경 이력은 본사만 조회하며, 공장에도 보일 수 있는 공용 변경 이력에는 원문 가격과 입력 사유를 넣지 않습니다.
- 새 작업을 임의로 생성하거나 기존 작업·샘플·수량·제품 원가를 변경하지 않습니다. 백업 도구의 전체 공개 스키마 수집에는 새 단가·이력 테이블도 포함됩니다.

별도 검증 프로젝트에서 기존 001~012 다음에 **013 → 014 → 015**를 순서대로 적용하고 새 앱을 빌드해 확인합니다. 현재 운영 데이터에 예시 단가를 일괄 입력하거나 새 테이블을 자동 배포하지 않습니다. 검증 후 운영 수동 적용 여부는 PR 검토 범위에 포함합니다.

주요 파일은 `ProcessingUnitPricePanel.tsx`, `processing-prices.ts`, `processing-prices-repository.ts`, `sig-eulji.ts`, `SettlementTemplateExport.tsx`입니다. 자동 시험 결과와 실제 운영 검증의 구분은 [테스트 결과](TEST_RESULTS.md)를 확인하세요.
