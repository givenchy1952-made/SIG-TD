# 보관된 생산 차수 PO 복구

생산 차수에는 특정 PO의 ID가 연결됩니다. 같은 스타일에서 다른 메일을 발송해도 연결된 PO가 미발송이면 **PO 발송 대기**로 표시됩니다. 연결된 초안을 보관하면 발송할 수 없지만, 원래 연결과 문서는 보존됩니다.

## 정확한 발주서가 보관된 초안에 있는 경우

1. 관리자 계정으로 해당 스타일의 **PO** 탭을 엽니다.
2. **보관된 초안** 중 이번 프로젝트·전체 품번·차수·사이즈별 수량이 맞는 문서를 확인합니다.
3. **연결된 초안 복원**을 누르고 사유를 입력한 뒤 **미발송 초안 복원 확인**을 누릅니다.
4. 복원은 메일을 보내지 않습니다. 기존 PO ID·차수 연결·본문·수신인·첨부·비교 원본을 유지하며 보관 상태만 해제합니다.
5. 수신인과 발주 내용을 확인한 뒤 **PO 메일 발송 → 발송 확인**을 진행합니다. 발송 접수 후 해당 차수가 **업체 회신 대기**로 바뀝니다.

이 복원 기능은 기존 저장 RPC를 사용하므로 015까지 적용된 서버에서 추가 SQL 없이 사용할 수 있습니다. 현재 담당 공장이 같고 발송·협의·승인·생산·입고 이력이 없는 보관 초안만 복원 버튼을 제공합니다. 오래된 PO 버전의 저장은 서버에서 거부합니다.

## 정확한 발주서를 이미 발송한 경우

메일 제목이 비슷하다는 이유로 다시 발송하거나 임의로 연결하지 않습니다. 실제 발송 본문·첨부 발주서의 프로젝트·전체 품번·컬러·업체·사이즈별 수량을 확인합니다.

015가 적용된 기존 프로젝트에 [016_archived_production_po_recovery.sql](../supabase/migrations/016_archived_production_po_recovery.sql)을 추가 적용하면, 발송된 PO의 **기존 생산 차수에 연결** 목록에서 보관 초안이 연결된 미진행 차수도 선택할 수 있습니다. 016 적용 전에는 이 교체 기능만 비활성화되고 기존 조회·연결·초안 복원 기능은 유지됩니다.

1. 확인한 발송 PO에서 **기존 생산 차수에 연결**을 누릅니다.
2. 차수와 수량을 비교하고 **보관된 미발송 초안 연결 교체 확인**을 체크합니다.
3. 실제 문서 확인, 필요한 원본·누적 수량 범위 확인과 사유를 입력합니다.
4. **확인한 발송 PO로 연결 교체**를 누릅니다. 이 작업은 메일을 보내지 않습니다.

교체 RPC는 기존 초안·새 PO·차수의 버전을 모두 검사하며 한 트랜잭션에서 기존 015의 문서·프로젝트·컬러·업체·수량 검증을 재사용합니다. 실패하면 기존 연결과 모든 감사 기록이 함께 롤백됩니다. 업체 회신·승인·생산 시작·입고·마감·조건 변경 이력이 있거나 이전 PO에 발송 시도·접수 흔적이 있으면 교체를 거부합니다. 기존 문서와 새 문서, 연결 전 차수와 담당자·사유는 본사 전용 변경 불가 이력으로 보존합니다.

## 화면 표시

- 차수 수정의 **연결 PO**에는 보관된 연결 문서도 표시합니다. 보관된 연결을 `미연결`처럼 표시하지 않습니다.
- 협의 화면과 PO 카드에서 **보관된 초안이 생산 차수에 연결**된 상태를 안내합니다.
- 일반 미연결 PO, 보관된 초안, 실제 발송 접수와 본사 최종 승인은 각각 기존 업무 상태를 유지합니다.
