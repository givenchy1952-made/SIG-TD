# 추가 업무 기능 설정·사용 안내

회사 Microsoft 365 계정으로 담당자별 PO를 발송하려면 [Outlook 연결 가이드](OUTLOOK_SETUP.md)를 따르세요. 아래 Resend 키·도메인 설정은 기존 Resend 방식의 안내입니다. Outlook은 회사 공용 Microsoft 앱의 공개 ID 두 개와 담당자별 로그인 승인을 사용합니다.

오더 Excel 가져오기, 프로그램에서 PO 메일 발송, 부분 출고, 실제 마감 양식 채우기, 직원별 담당 공장 배정, 휴가·런칭 일정, 중화 라벨, 비와이 자수 기능의 사용 절차입니다. 기본 설치·계정 승인·Vercel 배포는 [README](../README.md)를 먼저 확인하세요.

003이 없어도 기본 샘플·생산 화면은 열리고 추가 업무 저장에 설정 안내를 표시합니다. 004가 없으면 단가 저장과 SIG 을지 자동 다운로드를 비활성화합니다. **005가 없으면 새 프로젝트 등록·반차 구분·품질 검사·치수표 저장만 설정 안내를 표시**하며 기존 003·004 업무를 유지합니다. 파일 분석·다운로드와 실제 DB 저장은 별개입니다. SQL 적용 후 새로고침하세요.

## Excel 오더 수량 가져오기

승인된 관리자·본사 직원이 사용할 수 있습니다. 지원 파일은 암호화되지 않은 `.xlsx` 또는 **UTF-8·CP949 CSV**, 최대 10MB입니다. CSV는 UTF-8을 먼저 판독하고 CP949를 자동으로 지원하며 인식한 인코딩을 표시합니다. Excel은 최대 30개 시트, Excel·CSV 모두 시트당 10,000행·200열을 지원합니다. 파일은 브라우저에서 읽고 검증합니다. 큰 Excel은 **첫 탭 ORDER QTY만 선택하여 CSV UTF-8로 저장**한 뒤 가져오세요. CSV에는 이미지·다른 시트가 포함되지 않습니다.

1. 일반 열 연결은 등록된 스타일·컬러를 대상으로 합니다. SIG 형식의 없는 품번·컬러는 아래 **스타일·프로젝트 등록** 단계를 먼저 진행할 수 있습니다. SIG는 F열 전체 품번만 읽으며 I열을 사용하지 않습니다.
2. 원본 파일을 선택하고 사용할 시트·머리글 행을 확인합니다. 자동 인식한 열도 반드시 확인하세요.
3. 가로 형식(XXS·XS·S·M·L·XL별 열) 또는 세로 형식(품번·컬러·사이즈·수량)을 선택하고 각 열을 연결합니다.
4. **기존 오더 교체** 또는 **기존 오더에 추가**를 고릅니다. 교체는 파일 수량으로 바꾸고, 추가는 현재 오더에 더합니다.
5. 변경 전·파일 수량·변경 후 수량과 모든 오류를 확인합니다. 기본적으로 중복 품번·사이즈와 누락 사이즈는 오류입니다. 합산·누락 0처리는 사용자가 명시적으로 허용할 수 있습니다.
6. 변경 사유를 입력하고 **검증된 오더 적용**을 누릅니다.

미등록 품번·컬러를 수량 적용 과정에서 임의 생성하지 않습니다. SIG 등록 단계에서 본사가 기본 정보를 확인해 별도로 등록합니다. 음수·소수·범위 초과 수량, 매칭 실패, 중복·누락 등 오류가 있으면 적용하지 않습니다. 수식 자체를 실행하지 않고 파일에 저장된 계산 결과만 읽습니다. 계산 결과가 없는 수식은 Excel에서 계산한 뒤 저장해야 합니다.

SIG 형식의 원본 참조 정보도 아래 설명에 따라 함께 저장합니다. 적용은 선택한 전체 변경에 대해 한 번의 서버 트랜잭션으로 처리합니다. 어느 스타일이든 미리보기 이후 버전이 바뀌거나 권한·형식 검증이 실패하면 **전체가 취소**됩니다. **최신 데이터로 다시 검증**한 뒤 수량을 대조하세요. 출고·입고 수량과 생산 체크리스트는 변경 대상이 아닙니다.

### SIG ORDER QTY 형식과 원본 참조

대용량 Excel 대신 다시 제공된 CSV를 실제로 읽었습니다. 파일은 **CP949, 33행·153열**이며, 실제 항목 머리글은 **7행**, 선택 열에 데이터가 있는 행은 **8행 한 개**입니다. 여섯 사이즈 합계는 **4,138개**로 AY와 일치합니다. 이 CSV는 다시 저장하지 않고 업로드할 수 있습니다. 상단 3행의 사이즈 요약보다 F의 스타일코드·AY의 TOTAL QTY가 있는 실제 머리글을 우선 인식합니다. 실제 파일의 로컬 파싱·대조를 수행했으며 운영 DB에는 자동 적용하지 않았습니다. 일반 형식과 별도로 **파일 형식 → SIG ORDER QTY**를 선택하면 다음 열 위치를 적용합니다.

| 원본 열 | 적용 |
| --- | --- |
| `F` | 품번·컬러의 유일한 기준. 마지막 영문 두 자리를 컬러로, 나머지를 기본 스타일 코드로 매칭. **I열은 사용하지 않음** |
| `AQ, AR, AS, AT, AU, AV` | 각각 `XXS, XS, S, M, L, XL` 오더 수량 |
| `AY` | 여섯 사이즈 합계와 대조하는 총수량 |
| `A` | 프로젝트 코드 |
| `L, M` | 년도/시즌, 프로젝트 명칭 |
| `S, V` | 발주 요청일, 생산구분 |
| `W, X, Y` | 생산처, 제조국, 생산 담당자 |

총 16개 열의 원본 제목·값, 파일명·시트명·행 번호를 오더 수량과 함께 보관합니다. 실제 CSV의 이미지 열 `#NAME?`나 선택 범위 밖 부자재 열 `#REF!`는 저장 대상이 아니므로 선택 열에 영향이 없으면 가져오기를 막지 않습니다. 선택한 열의 잘못된 수량, Excel 오류 셀, CSV에 남은 정확한 Excel 오류 문자열(`#REF!`, `#NAME?` 등)은 계속 차단합니다. 일반 메모의 `#` 문자는 오류로 취급하지 않습니다. 수량이 같아도 참조 정보가 다르면 변경 대상으로 표시합니다. 미등록 프로젝트·스타일·컬러는 **자동 등록 예정**으로 표시합니다. **검증된 오더 적용** 한 번으로 필요한 기본 정보와 수량을 함께 처리합니다.

저장 후 스타일 상세의 **ORDER QTY 원본** 탭에서 등록 시점의 원본을 확인합니다. 승인된 본사는 `A/L/M/S/V/W/X/Y` 참조 값을 수정할 수 있습니다. `F`, `AQ~AV`, `AY`는 가져온 시점의 스냅샷으로 유지합니다. 실제 오더 수량을 수기로 바꿀 때는 **메인 생산**에서 수정합니다. 원본 참조를 편집했다고 오더 수량이 바뀌거나, 수기를 바꿨다고 가져온 당시 원본 수량이 바뀌지는 않습니다. `order_source_records`는 본사 전용이며 별도 버전·사유를 검사합니다.

### 전체 품번 자동 인식과 등록·수량 적용

1. 파일을 선택하면 F열 전체 품번을 자동으로 읽습니다. F가 기본 품번이면 B열 예산코드가 정확히 `A 프로젝트 코드 + F 기본 품번 + 영문 두 자리`인 경우에만 보완합니다. I열은 사용하지 않습니다. 판독값을 수정해야 할 때만 **품번 판독값 수정 (선택)**을 엽니다.
2. 기존 품번은 재사용하고 미등록 프로젝트·품번·컬러를 자동 등록 예정으로 표시합니다. 품번별 등록·프로젝트 연결 버튼과 별도의 일괄 등록 단계는 없습니다.
3. 프로젝트는 A열 코드를 기준으로 만들고 M 명칭·L 시즌을 사용합니다. 이미 같은 코드가 있으면 기존 프로젝트를 재사용하며, 명칭·시즌이 충돌하면 데이터 확인을 요청합니다.
4. W열의 생산처가 등록 공장에 유일하게 일치하면 자동 연결합니다. 담당자는 Y열의 이름·이메일을 승인된 본사 계정과 연결해 컬러별로 저장합니다. Y가 빈칸이면 미지정으로 두며 업로드한 사람으로 채우지 않습니다. 동명이인·미등록 이름은 그룹별로 한 번 연결합니다. 기존 품번의 공장 배정은 유지합니다. 매칭되지 않은 생산처만 **업로드 기본 설정 (선택)**에서 그룹별로 연결합니다.
5. AO 제목이 입고예정일이고 실제 ISO 날짜가 있으면 신규 납기로 가져옵니다. 날짜가 없으면 **납기 미정**으로 저장하고, PO 발송 시 요청 납기를 입력합니다. 발주 요청일이나 오늘 날짜를 납기로 대신 넣지 않습니다.
6. **검증된 오더 적용**을 한 번 누릅니다. 전체 파일 검증 후 프로젝트·품번을 등록하고 AQ~AV 수량·원본 참조·새 생산 차수를 적용합니다.

버튼 하나로 연속 실행하지만 프로젝트·스타일 등록과 수량 일괄 적용은 별도 서버 트랜잭션입니다. 수량 적용에 실패하면 기본 정보는 남을 수 있으며 화면에서 이를 안내합니다. 수량 적용 자체는 원자적으로 처리하고, 기존 스타일과 원본 정보의 버전은 처음 파일을 읽은 시점을 유지하여 동시 수정 내용을 덮어쓰지 않습니다. 스타일 등록 후 조회 실패도 저장 완료와 구분하여 안내합니다. 시트·제목 행·형식을 바꾸면 준비한 등록 정보를 취소합니다.

기존 스타일의 프로젝트 자동 연결은 해당 스타일의 모든 컬러에 적용하며 과거 생산 차수의 프로젝트 기록은 유지합니다. 기존 수량·공장·다른 생산 내역은 보존하며, 업로드한 컬러의 담당자만 Y열에 맞춰 갱신합니다. 등록·수량 적용은 실제 출고·입고 수량을 자동 생성하지 않습니다. 컬러별 담당자와 미지정 등록에는 011_import_color_owners.sql이 필요하며 프로젝트별 생산 차수의 기존 006~009 설정도 필요합니다.

## PO 메일 발송

승인된 관리자·본사 직원이 초안을 만들고 발송합니다. 외부 공장은 배정된 스타일의 이력을 조회합니다. 체험 모드에서는 초안과 이력을 살펴볼 수 있지만 실제 이메일을 발송하지 않습니다.

1. 스타일의 담당 공장과 PO 수신 이메일을 확인합니다.
2. **PO 작성**에서 PO 납기일·수신 이메일·제목·내용을 입력하고 변경 사유와 함께 **PO 초안 저장**합니다. 초안 저장은 발송이 아닙니다.
3. 저장된 내용의 납기·수신인·제목을 검토하고 **PO 메일 발송 → 발송 확인**을 누릅니다.
4. 접수 결과·서비스 접수 ID·시도 이력을 확인합니다. 납기는 서버가 실제 발송 제목·본문에 포함합니다.

PO에서 기존 스타일 첨부파일을 선택하면 서버가 권한을 확인해 **PDF·JPG·PNG·WEBP 파일 1개(최대 10MB)를 실제 메일에 첨부**합니다. 선택한 파일명과 수신인을 발송 전에 확인하세요. 파일이 없거나 접근·형식·용량 검증에 실패하면 성공 처리하지 않습니다. `.eml` 다운로드는 첨부파일이 없는 메일 초안 생성이며 실제 발송과 구분합니다.

| 서버 상태 | 화면 의미 | 다음 행동 |
| --- | --- | --- |
| `draft` | 초안·미발송 | 내용 확인 후 발송 |
| `sending` | 발송 요청 처리 중 | 중복 요청 금지, 실제 접수 결과 확인 |
| `sent` | **발송 접수** | 메일 서비스가 요청을 수락하고 접수 ID를 반환한 상태 |
| `failed` | 발송 실패 | 오류 원인 수정 후 허용된 동일 내용 재시도 또는 새 PO 작성 |
| `unknown` | 접수 여부 확인 필요 | 자동·사용자 재발송 차단, 서비스 관리자 대조 필요 |

`sent`는 수신자 편지함 도착·열람·공장 확인을 의미하지 않습니다. 스팸 분류·반송·배달 결과는 실제 메일 서비스에서 확인해야 합니다. 네트워크 시간 초과 등으로 결과가 불명확하면 `unknown` 또는 처리 중 상태로 남을 수 있습니다. 임의로 성공 처리하거나 중복 발송하지 말고, 메일 서비스 기록과 접수 ID·시도 일시를 대조한 뒤 신뢰할 수 있는 관리자 절차로 정리하세요. 자동 조정 화면은 제공하지 않습니다.

발송을 시도한 PO는 내용을 수정하지 않습니다. 정정은 **새 PO로 복사**하여 새 기록으로 작성합니다. 아직 발송을 시도하지 않은 초안만 보관할 수 있으며 원본·시도 이력은 남습니다.

### 실제 메일 서비스 설정

이 기능에는 Supabase Edge Function **send-po-email**과 Resend 계정의 API 키·검증된 발신 주소가 필요합니다. 클라이언트 공개 키와 별개의 **서버 전용 설정**입니다. 실제 자격정보가 없는 개발 검증에서는 메일 발송 완료로 처리하지 않습니다.

Supabase CLI를 설치·로그인한 뒤 저장소 루트에서 설정합니다. 예시 파일은 `supabase/.env.functions.example`입니다.

```bash
cp supabase/.env.functions.example supabase/.env.functions.local
```

복사한 로컬 파일에 다음 **서버 전용 세 값만** 입력하세요. 호스팅 함수의 `SUPABASE_` 기본 변수는 플랫폼이 제공하며 Secrets로 다시 설정하지 않습니다. 로컬 파일은 Git에 넣지 않습니다.

| 변수 | 설정 |
| --- | --- |
| `RESEND_API_KEY` | 발송 권한이 있는 Resend API 키 |
| `PO_FROM_EMAIL` | Resend에서 검증된 발신 주소. 예: `FIVE SPACE / SIG <po@YOUR_VERIFIED_DOMAIN>` |
| `PO_ALLOWED_ORIGINS` | 허용할 앱 origin을 쉼표로 구분. 예: `https://YOUR_APP.vercel.app,http://localhost:5173` |

origin에는 URL 경로·끝 슬래시·와일드카드 없이 프로토콜과 호스트·필요한 포트만 지정합니다. 운영 주소와 시험 주소를 실제로 쓰는 값만 등록하세요. Resend의 발신 도메인·주소 검증과 필요한 DNS 설정을 먼저 완료해야 합니다.

```bash
supabase secrets set --project-ref YOUR_PROJECT_REF --env-file supabase/.env.functions.local
supabase functions deploy send-po-email --project-ref YOUR_PROJECT_REF
```

`SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`는 호스팅된 Supabase Edge Function의 기본 제공 환경을 사용합니다. `service_role`은 이 함수 서버 내부에서 결과 확정에만 사용하며 프론트엔드로 전달하지 않습니다. 키를 Vercel의 `VITE_` 변수·Git·로그·채팅에 넣지 마세요. 함수는 Resend의 `api.resend.com`으로 HTTPS 발송 요청을 보냅니다.

`supabase/config.toml`의 `send-po-email` 설정은 `verify_jwt=false`입니다. 이 함수는 각 요청의 Bearer 토큰을 **Auth 서버의 `getUser`로 직접 검증**하고, 사용자 JWT로 호출하는 DB RPC에서 승인된 본사 계정 권한을 다시 확인합니다. 따라서 Gateway JWT 설정과 별개로 인증을 강제합니다. 이 검증 코드를 제거하지 마세요. 제공된 config를 사용하지 않는 별도 배포 절차에서는 동일한 함수 설정을 적용해야 합니다.

배포 후 최신 앱을 열고 승인된 본사 시험 계정으로 PO 한 건을 작성합니다. 실제 수신인·제목·납기를 확인하고 명시적으로 발송한 뒤 Resend 접수 내역 및 수신함을 각각 확인하세요. 함수 배포·서버 Secrets 등록과 Vercel 클라이언트 배포는 서로 다른 단계입니다. 잘못된 origin·미검증 발신 주소·미등록 키는 성공 처리하지 않습니다.

## 메인 생산 수량표와 차수별 출고

부분출고는 별도 탭이 아니라 **메인 생산 → 사이즈별 수량** 안에 있습니다. 오더·실 출고 합계·실 입고와 이전 입력 수량·1차·2차 등의 차수별 수량을 한 표에서 확인합니다. **패킹리스트 수량 행은 표시하지 않으며** 기존 저장 값과 패킹리스트 확인 공정 체크는 보존합니다.

외부 공장 또는 관리자가 컬러별 **출고 차수 추가**로 1차·2차 등의 실제 출고일, 운송장, XXS~XL 수량과 메모를 입력합니다. 본사 직원은 조회·다운로드할 수 있습니다. 기존 생산 화면의 입력 수량은 첫 차수 저장 시 **이전 입력 수량** 기준으로 보존하고, 유효한 차수별 출고만 더해 누적 실 출고를 계산합니다.

기존 수량을 다시 1차 출고에 복사하면 중복 합산될 수 있으므로 첫 저장 전에 기준 수량을 확인하세요. 기록을 정정할 때 원본을 제거하지 않고 사유와 함께 수정·무효 처리합니다. 무효 차수는 누적 합계에서 제외하되 이력은 남깁니다. 입고 수량은 기존대로 관리자만 입력합니다.

스타일·출고 차수 버전을 함께 검사합니다. 다른 사람이 수량이나 스타일을 먼저 저장하면 누적 합계를 덮어쓰지 않고 충돌을 안내합니다. 차수 기록이 시작된 컬러의 실 출고 합계는 차수 원장을 통해 관리하세요.

## SIG 을지 자동 작성

제공된 **SIG_을지.xlsx**의 **대금지급(을)** 원본을 기본 양식으로 포함합니다. 양식에는 항목 제목·서식·수식만 있으며 실제 업무 행은 넣지 않습니다. 개인 문서 속성·로컬 경로는 정리했습니다. 매번 양식을 다시 업로드하거나 각 열을 연결할 필요가 없습니다.

1. 스타일 상세의 **을지·단가**에서 컬러를 선택하고 **단가·을지 정보 수정**을 누릅니다.
2. **을지 프로젝트 코드**, **장당 원가(KRW)**, **제품·원단·라벨 구분**을 입력하고 변경 사유와 함께 저장합니다. 프로젝트 코드를 별도로 지정하지 않았으면 현재 연결한 프로젝트 코드를 먼저 참조하고, 없으면 해당 컬러의 ORDER QTY A열에서 일치하는 코드 하나를 참조합니다. 프로젝트 UUID·임의 명칭을 코드 대신 넣지 않습니다.
3. **메인 생산**의 현재 오더 수량, 관리자가 입력한 실제 입고 수량과 해당 컬러의 실제 입고일, 현재 담당 공장·본사 담당자를 확인합니다.
4. 스타일 상세 상단 **을지 다운로드**는 현재 선택한 컬러를 대상으로 엽니다. 여러 대상을 선택하려면 본사 대시보드에서 공장·프로젝트·스타일·컬러를 검색·필터한 뒤 **을지 양식 다운로드 → SIG 을지 자동 작성**을 엽니다.
5. 지정 열 미리보기와 누락 안내를 확인하고 **을지 다운로드**를 누릅니다. 현재 선택 범위의 스타일+컬러마다 한 행을 작성합니다.

| 을지 열 | 자동 입력 기준 |
| --- | --- |
| `A` | 저장한 을지 프로젝트 코드 → 현재 연결한 프로젝트 코드 → 일치하는 ORDER QTY A열 코드 순서 |
| `C` | 해당 컬러의 실제 입고일 |
| `D` | 현재 담당 공장에 등록된 업체명 |
| `I` | 기본 스타일 코드 + 마지막 영문 두 자리 컬러코드 |
| `N` | 저장한 장당 원가 |
| `O` | **1** |
| `P` | 해당 컬러의 현재 PO 오더 6사이즈 총수량 |
| `Q` | **P와 동일** |
| `R` | 해당 프로젝트·스타일·컬러의 현재 실제 입고 6사이즈 총수량 |
| `S` | **원단: YDS**, **제품·라벨: EA** |
| `T` | **N × R**, 사용자가 확인한 **부가세 제외 금액** |
| `U, V` | 원본 부가세 `T × 10%`와 부가세 포함 합계 수식 유지 |
| `W` | 현재 스타일에 지정된 본사 담당자 이름 |

원가는 **생산을 진행할 때마다 본사 관리자 또는 팀원이 직접 입력·수정**합니다. 스타일·컬러·프로젝트에 맞는 현재 원가를 확인하고 저장하며, 오더 CSV나 다른 생산의 원가를 자동으로 가져오지 않습니다. 기존 **을지·단가** 탭은 스타일·컬러의 현재 단가를 관리하고 이전 값은 전용 이력에 남깁니다. **007~009 적용 후 새 생산 건은 생산 차수·마감 탭에서 프로젝트·PO 차수별 단가와 실제 입고를 따로 기록하고 마감을 확정**합니다. 확정 을지는 당시 금액을 사용합니다. [새 생산 흐름](PRODUCTION_ROUNDS.md)을 확인하세요.

실제 입고를 오더·출고 수량으로 대체하지 않고, 다른 프로젝트·컬러를 합산하지 않습니다. CSV의 생산처·담당자 참조가 현재 업무 배정을 덮어쓰지 않습니다. 기존 **업체 마감 금액**도 을지 단가·T를 대신하지 않습니다. 다시 받은 CSV는 선택 열에 원가가 없고 원본 단가 열도 비어 있어, 원가는 본사에서 직접 입력해야 합니다.

단가는 미입력 `null`과 명시적 **0원**을 구분하며 0~1,000,000,000원·소수 둘째 자리까지 저장합니다. 프로젝트 코드·단가·입고일·업체·담당자 등 필수 정보가 빠진 대상이 하나라도 있으면 **전체 다운로드를 막고 해당 컬러를 안내**합니다. 없는 금액·날짜를 임의로 채우지 않습니다. 범위를 줄이려면 마감 화면의 필터를 조정하세요.

004의 `settlement_terms`와 `settlement_terms_audits`는 **승인된 본사·관리자 전용**입니다. 단가·프로젝트 코드·이전/이후 값·사유를 전용 이력에 보존하고 버전 충돌을 검사합니다. 외부 공장에는 단가·전용 이력·SIG 을지 자동 작성이 노출되지 않습니다. 저장하지 않은 편집과 다른 사람의 먼저 저장한 값은 자동으로 덮어쓰지 않습니다.

SIG 자동 작성은 제공된 원본의 OOXML 패키지를 사용합니다. 표 범위·자동 필터·입력 행·합계 범위를 데이터 수에 맞춰 확장하고, 행 서식·원본 표 수식·인쇄 설정을 유지합니다. 변경된 데이터의 계산 순서는 다시 계산하도록 갱신합니다. 다운로드 후 실제 Excel에서 프로젝트별 금액과 인쇄 결과를 대조하세요. 이 파일 생성 검증과 운영 DB 적용·실제 지급 업무 승인은 별개입니다.

### 다른 마감 양식 사용

기존 기능은 **다른 양식 · 직접 열 연결**에서 유지합니다. 암호화되지 않은 `.xlsx` 최대 10MB를 올리고 시트·머리글·데이터 시작/마지막 행·연결 열을 지정한 뒤 **양식 채워서 다운로드**합니다. 합계·서명란은 데이터 영역에 포함하지 않습니다. 이 모드에서는 행을 삽입하지 않고 지정 범위의 연결한 열만 바꿉니다. 연결하지 않은 열과 다른 영역은 유지합니다.

다른 양식의 데이터 영역에 병합·수식·배열/공유 수식·행 부족 등 안전하게 쓸 수 없는 구조가 있으면 중단합니다. ExcelJS가 지원하지 않는 특수 개체·외부 연결·고급 서식의 완전 보존은 보장하지 않으므로 결과를 원본과 비교하세요. 이 일반 모드의 한계와 고정 SIG 원본에 적용하는 자동 작성은 구분합니다.

## 직원별 담당 공장

관리자는 **사용자 관리 → 직원 행의 담당 공장 배정**에서 승인된 활성 본사 직원·관리자에게 복수 공장을 선택하고 사유를 입력해 저장합니다. 선택을 모두 해제하면 업무 배정을 비울 수 있습니다. 배정 버전이 바뀌면 내 선택을 유지한 상태로 충돌을 안내합니다.

이 배정은 **업무 담당 구분**입니다. 본사 직원의 기존 전체 스타일 조회 권한을 제한하거나 외부 공장의 접근 범위를 넓히지 않습니다. 외부 공장 계정의 소속 공장은 기존 사용자 권한 수정에서 따로 지정합니다.

## 개인 휴가·제품 런칭·협력업체 휴가

005 적용 후 개인 휴가에서 **종일 / 오전 반차 / 오후 반차 / 반반차 (2시간)**를 고릅니다. 반차·반반차는 시작일과 종료일이 같은 당일 일정입니다. 2시간 반반차는 시작 시간을 직접 지정하면 종료 시간을 정확히 120분 뒤로 계산하며, 자정을 넘기는 시간은 저장하지 않습니다. 회사의 출퇴근·점심시간을 임의로 가정하지 않습니다. 캘린더 월간·주간·목록에 구분과 시간이 표시되며 기존 개인·본사·공장 공개 범위는 그대로 유지합니다.

**프로젝트 캘린더 → 일정 등록**에서 유형, 일정명, 시작일·종료일, 메모와 사유를 입력합니다. 여러 날의 일정은 종료일을 포함한 기간 전체에 표시되며 클릭하면 상세·수정·이력을 엽니다. 기존 스타일 기반 샘플·생산 일정도 함께 유지됩니다.

| 유형 | 조회 | 등록·수정 |
| --- | --- | --- |
| 개인 휴가 `private` | 본인만, 다른 관리자도 열람 불가 | 본인 |
| 개인 휴가 `hq` | 승인된 본사 구성원 | 본인·관리자 |
| 제품 런칭 `all` | 승인된 본사·공장 구성원 | 본사 구성원 |
| 협력업체 휴가 `hq` | **본사만** | 본사 구성원, 공장 지정 필수 |

외부 공장은 자신의 비공개 개인 휴가만 등록할 수 있습니다. 협력업체 휴가는 공장 계정의 캘린더·알림·변경 이력에서 제외하고 SQL RLS에서도 차단합니다. 개인 휴가의 과거 비공개 내용이 공개 범위 변경으로 유출되지 않도록 일정 전용 감사 이력에 현재·과거 공개 범위를 함께 적용합니다. 삭제는 캘린더에서 제외하는 보존 삭제입니다.

## 중화 라벨·비와이 자수

관리자 **작업 종류 관리**에서는 제공된 고정 종류의 **활성·비활성 상태만** 변경합니다. 새 종류를 추가하거나 기존 명칭·작업 구분을 바꿀 수 없습니다. 사용자 제공 목록은 라벨 23종·비와이 자수 33종이며, `src/lib/default-operation-catalogs.json`의 실제 이름을 TypeScript 로더와 003 SQL에서 사용합니다. 003 적용 시 고정 목록만 등록하고 실제 작업 주문·생산 수량은 만들지 않습니다. 임의의 새 품목을 체험 예시처럼 추가하지 않습니다.

스타일 상세의 **가공·품질 관리 → 중화 라벨 / 비와이 자수**에서 승인된 고정 종류를 선택하고 사양·상태·메모와 다음 항목을 입력합니다.

| 업무 | 수량 | 일자 |
| --- | --- | --- |
| 중화 라벨 | 발주 수량, 로스 수량, 총 필요 수량 자동 합산 | 발주일, 입고 예정일 |
| 비와이 자수 | 요청 수량, 완료 수량, 잔여 수량 자동 계산. 완료는 요청을 초과할 수 없음 | 요청일, 예정일, 완료일 |

작업 편집 화면에서도 자유 입력한 이름을 종류로 추가하지 않습니다. 사용하지 않는 종류는 관리자가 비활성화하며 이전 기록과 이름은 보존됩니다.

관리자·본사 직원이 작업 지시를 작성하고, 외부 공장은 배정된 스타일에서 허용된 범위를 조회합니다. 저장은 스타일·작업별 버전과 권한을 검사하며 변경 사유를 보존합니다.

## 가공·품질 관리와 상의·하의 치수표

**가공·품질 관리**는 중화 라벨·비와이 자수·품질 검사를 함께 보는 탭 이름입니다. **품질 검사**의 대상은 **아우터, 니트, 티셔츠, 바지, 가방, 악세사리, 모자** 중에서 고릅니다. 컬러별 검사 수량·진행 상태·요청일·완료일·결과 메모를 본사가 입력하고 변경 사유와 함께 **품질 검사 저장**합니다. 배정된 공장은 조회할 수 있지만 품질 검사 지시를 변경하지 않습니다.

**메인 생산 → 출입고 및 정산**의 **사이즈 측정**은 **상의 / 하의**로 나눈 표입니다. **사이즈 측정 수정**을 누르고 위치별 편차와 **XXS·XS·S·M·L·XL·XXL** 치수를 입력한 뒤 사유와 함께 **사이즈 측정 저장**합니다. 생산 오더 수량의 6사이즈와 측정표의 XXL 칸은 별개입니다.

상의 기본 위치는 총장(옆목)·가슴·허리·밑단·어깨·목 너비/깊이·암홀·소매 기장/통/입구·화장이고, 하의는 허리·총장·엉덩이·밑단·앞/뒷 밑위·허벅지·인심입니다. 필요하면 위치를 추가·삭제하되 상의·하의 각각 1~30개를 유지합니다. 단위는 **cm**, 값과 편차는 0~1,000·소수 둘째 자리까지이며 **빈칸은 미측정, 0은 입력한 값**으로 구분합니다. 예시 이미지의 수치를 실제 값으로 자동 입력하지 않습니다.

기존 서술식 측정 기록은 읽기 전용 보관 영역에서 볼 수 있습니다. 본사와 배정된 공장이 측정표를 입력할 수 있고, 공장은 같은 저장 문서의 품질 검사 값을 바꿀 수 없습니다. 품질 검사·측정표는 별도 버전과 이력으로 저장하며 실 출입고 수량을 변경하지 않습니다. 다른 사용자가 먼저 저장하면 입력을 유지한 채 충돌을 안내합니다.

## 실제 서비스 확인 항목

자동화 검증의 실제 결과는 [TEST_RESULTS.md](TEST_RESULTS.md)에 기록합니다. 운영 연결 후에는 다음을 별도로 확인하세요.

- 실제 오더 원본에서 F열 단독 품번·컬러와 AQ~AV 수량, A 코드·M 명칭을 대조합니다. 미등록 기본 정보 등록 후 별도 수량 적용과 두 사용자 충돌을 확인합니다.

- 본사 계정으로 단가·프로젝트 코드를 변경하고 이력·충돌을 확인합니다. 공장 계정의 직접 API 요청에서도 단가·전용 이력이 차단되는지 확인합니다.

## 복수 선택 필터

프로젝트 캘린더의 일정 종류·공장·프로젝트·제품, 스타일 현황의 시즌·프로젝트·공장·제품과 상세 필터에서 여러 항목을 체크할 수 있습니다. 선택 창에서 항목 검색이 가능하며 **선택해제**로 모두 해제한 뒤 필요한 항목만 체크하고 **완료**를 누릅니다. 같은 필터 안에서는 선택한 항목 중 하나가 맞으면 포함하고, 다른 필터끼리는 모두 맞아야 포함합니다. 선택해제 상태는 결과 없음이고 **전체보기**는 해당 필터 제한을 해제합니다. 필터별 표시의 X 또는 필터 초기화로 해제합니다.

캘린더 월간·주간 전환에도 선택은 유지합니다. 샘플·생산/납기·결제·개인휴가·제품런칭·협력업체 휴가를 구분하며, 협력업체 휴가 선택지는 공장 계정에 표시하지 않습니다. 프로젝트·제품에 속하지 않는 휴가·런칭은 기존처럼 독립 일정으로 표시하고 화면에 그 기준을 안내합니다. 모든 집계·일정 목록은 같은 필터 결과를 사용합니다.

목록과 CSV·Excel·을지의 현재 데이터는 선택한 프로젝트·제품·컬러 범위를 따릅니다. 같은 스타일의 컬러를 선택하면 전체 스타일 보기에서도 선택한 컬러의 합계와 생산 행만 내보냅니다. 기존 샘플·변경 이력은 보존합니다.

## 중화라벨·비와이 자수·품질검사 을지

스타일 상단 **을지 다운로드**, 또는 본사 목록의 **을지 양식 다운로드 → SIG 을지 자동 작성**에서 작성 항목을 선택합니다.

| 항목 | 업체명 D열 | 작업 범위 | 수량 |
| --- | --- | --- | --- |
| 메인 제품 | 현재 담당 공장 | 선택한 컬러별 | 기존 오더·실제 입고 수량 |
| 중화라벨 | 주식회사 중화라벨 | 스타일 공통 작업별 한 행 | P/Q 발주 수량, 로스는 X, R은 담당자 입력 |
| 비와이 자수 | BY컴퓨터자수 | 스타일 공통 작업별 한 행 | P/Q 요청 수량, R 등록된 완료 수량 |
| 품질검사 | **빈칸** | 선택한 컬러의 검사 항목 | P/Q 검사 수량, 완료·승인 및 완료일이 있을 때만 R 작성 |

L열에 작업명·검사 종류, X열에 사양·로스·상태·메모를 넣습니다. 무효 처리한 가공 내역은 제외합니다. 라벨·자수는 컬러별 작업 배분 정보가 없으므로 수량을 임의 분할하거나 컬러 수만큼 복제하지 않습니다. I에는 스타일 공통 품번, 품질검사는 컬러 포함 품번을 넣습니다.

가공·검사 단가는 저장된 값이 없어 N을 빈칸으로 두며 메인 제품 원가를 재사용하지 않습니다. 비어 있는 단가·실제 수량·입고일·프로젝트 코드는 담당자가 Excel에서 입력합니다. 품질검사의 업체명도 직접 입력합니다. T/U/V는 필요한 금액 정보가 채워질 때 계산하는 수식이며 입력 전에는 0원으로 확정하지 않습니다. 합계도 미작성 금액이 남아 있으면 비워 둡니다. 메인 제품의 기존 필수 정보 검증은 유지합니다. 저장되지 않은 편집 중에는 먼저 저장·취소하고 다운로드하세요.

이 두 기능은 기존 003~005 데이터를 조회해 파일을 생성하며 새 SQL은 없습니다.

## 프로젝트별 리오더와 업체 동의

006~009 SQL을 추가 적용한 이후 업로드마다 새 프로젝트·생산 차수를 만듭니다. 같은 품번·같은 수량도 별도 리오더로 등록할 수 있으며 이전 입고와 원가를 덮어쓰지 않습니다. 본사가 차수에 PO를 연결해 발송하고, 배정된 업체가 예상 납기와 생산 동의를 제출하면 생산 진행으로 전환됩니다. 가입 승인과 차수별 마감 절차는 [생산 차수 가이드](PRODUCTION_ROUNDS.md)에 정리했습니다.

## 여러 신규 품번을 한 번에 가져오기

SIG ORDER QTY 파일의 AQ~AV에서 단독 `-`는 Excel 회계 서식의 0으로 읽습니다. 음수·소수·수식 오류 및 AY 합계 불일치는 계속 차단하고, 원본 참조에는 `-`를 그대로 보관합니다. 일반 형식과 AY 합계의 하이픈을 임의로 0으로 바꾸지는 않습니다.

여러 신규 품번도 **오더 엑셀 업로드 → 파일 선택 → 검증된 오더 적용** 한 번으로 등록합니다. A열 프로젝트와 F열 스타일을 따로 등록하거나 행마다 확인할 필요가 없습니다. 등록 가능한 새 품번은 오류 대신 자동 등록 예정으로 표시합니다. W열에서 공장을 자동 연결하고, 매칭되지 않는 생산처만 그룹별로 한 번 선택합니다. 납기 미기재는 빈 값으로 보존합니다.

전체 파일의 수량을 검증한 뒤 필요한 기본 정보를 차례로 등록하고, 모든 대상의 오더 수량과 새 생산 차수를 일괄 적용합니다. 기존 품번의 공장·납기·출고·입고 이력은 보존하고, 업로드한 컬러의 담당자는 Y열을 따릅니다. 등록 중 연결 오류가 나면 일부 기본 정보가 남을 수 있으며, 오류 안내와 최신 데이터를 확인한 뒤 남은 등록·수량 적용을 진행합니다.

컬러별 담당자·빈 담당자 업로드는 011 SQL 적용 후 사용할 수 있습니다. 기존 프로젝트별 생산에 필요한 005~009 SQL과 메일 발송 설정은 기존 안내를 따릅니다. 구성원 탈퇴에는 별도로 010 SQL이 필요합니다. [최신 적용 안내](COLOR_OWNERS.md)를 확인하세요.
