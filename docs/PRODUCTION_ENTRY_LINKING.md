# 생산 수량·승인 원가·담당자 자동 연결

## 사이트에 적용하기

기존 001~025 적용 이력을 확인한 다음, Supabase SQL Editor에서 아래 파일을 순서대로 수동 실행하고 웹 변경을 배포합니다.

1. [026_main_production_sync.sql](../supabase/migrations/026_main_production_sync.sql)
2. [027_factory_owner_defaults.sql](../supabase/migrations/027_factory_owner_defaults.sql)

이 개발 작업에서는 운영 SQL을 실행하거나 운영 자료를 수정하지 않았습니다. 026이 없으면 기존 출고 차수·수동 실입고 화면을 유지합니다. 승인 원가 표시와 컬러·프로젝트 선택 연결 자체에는 추가 SQL이 필요하지 않습니다. 027은 공장 담당자 저장 시 현재 스타일까지 연결하기 위한 서버 처리입니다.

## 실출고는 한 번 입력

**스타일 상세 → 메인 생산 → 사이즈별 수량 → 실 출고 수량**에 XXS~XL의 현재 누적 출고 수량을 입력합니다. 실 출고 일자와 하단 변경 사유를 확인하고 **변경 저장**을 누릅니다. 같은 수량을 별도 출고 차수에 다시 입력하지 않습니다.

이전 출고 기준값과 출고 차수는 **출고 변경 이력**에서 확인합니다. 과거 수량을 삭제하지 않고 누적 수량의 증감 이력을 추가합니다. 기존에 같은 출고를 두 번 입력해 누적 수량이 부풀었다면, 실제 누적 수량으로 고친 뒤 사유와 함께 저장합니다. 과거 기록을 자동으로 추정해 삭제하거나 정리하지 않습니다.

공장은 기존에 배정된 스타일의 출고만 수정할 수 있습니다. 입고 확정 권한은 기존 관리자 범위를 유지합니다.

## 메인 입고 확정 → 차수 입고 자동 기록

1. **메인 생산 → 사이즈별 수량 → 실 입고 수량**에 XXS~XL의 현재 누적 입고 수량을 입력합니다.
2. **출입고 및 정산 → 실 입고 일자**를 확인합니다. 날짜가 비어 있으면 입고 확정 시 한국 날짜의 오늘을 사용합니다.
3. **입고 확정** 영역에서 연결할 생산 차수를 확인합니다. 같은 컬러·프로젝트에 미마감 차수가 하나면 자동 선택하며, 여러 개면 직접 선택합니다.
4. 하단 **변경 사유**를 입력한 뒤 **입고 확정**을 누릅니다.

누적 입고와 아직 차수에 연결되지 않은 수량을 함께 저장합니다. 예를 들어 메인 누적 100장 중 기존 차수 기록이 60장이면 이번에는 40장만 기록합니다. **생산 차수·마감 → 차수별 실제 입고**에 입고일·사이즈·당시 단가·금액이 자동 반영되며 수량을 다시 입력하지 않습니다.

기존 메인 입고 수량은 있지만 차수 기록이 없던 경우에도 수량을 다시 입력하지 않고 입고 확정으로 연결할 수 있습니다. 같은 누적 수량을 다시 확정해도 입고를 중복 생성하지 않습니다. 기존 차수 기록보다 누적 수량을 줄여야 한다면 해당 기록의 무효 처리와 사유를 먼저 확인합니다.

입고 대상 차수는 생산 시작과 최종 승인 단가가 확인되어야 합니다. 마감된 차수, 다른 컬러·프로젝트, 이미 다른 사용자가 수정한 버전에는 저장하지 않습니다. 입력을 수정하는 동안 화면을 옮기거나 통신 오류가 나더라도 서버에서 같은 요청의 중복 반영을 막습니다.

## 을지·단가는 승인 원가 사용

**생산 조건 협의·승인**의 본사 최종 승인 단가를 **을지·단가**에서 자동으로 읽습니다. 생산 차수가 있는 컬러는 장당 원가를 별도 입력하지 않습니다. 여러 차수가 있으면 해당 차수를 선택하며, 승인 전이나 연결이 불명확한 상태에서 다른 컬러·차수의 가격을 대신 사용하지 않습니다.

입고 수량과 금액은 선택한 차수의 기록을 사용합니다. 마감된 차수는 확정 당시의 단가·입고·금액을 유지합니다. 생산 차수가 없는 과거 스타일은 기존 수동 단가 관리 방식을 계속 사용할 수 있습니다. 예산 파일의 사전 원가 업로드와 생산 차수의 최종 승인 단가는 서로 다른 자료로 유지합니다.

## 공장 담당자 자동 배정

**사용자 및 기준 정보 → 사용자 관리 → 담당 공장 배정**에서 본사 구성원에게 공장을 연결합니다. 해당 공장의 승인된 활성 본사 담당자가 한 명이면 현재 스타일과 컬러에 자동 연결되고, 이후 저장하는 스타일·오더 등록·새 생산 차수에도 같은 담당자를 사용합니다.

한 공장에 담당자가 여러 명이거나 유효한 담당자가 없으면 임의의 첫 번째 사람을 고르지 않고 기존 명시 담당자를 유지합니다. 기존 생산 차수의 배정 스냅샷과 마감 당시 담당자는 바꾸지 않습니다. 이전 자료의 담당자를 일괄 변경하려면 공장 배정 내용을 확인하고 변경 사유와 함께 저장합니다.

## 클릭한 컬러·프로젝트 유지

스타일 목록이나 생산 차수 목록에서 컬러·프로젝트를 열면 **생산 조건 협의·승인 / 생산 차수·마감 / 메인 생산 / 을지·단가**가 같은 대상을 사용합니다. GR을 눌렀을 때 BK나 OT의 첫 번째 생산 오더를 대신 선택하지 않습니다.

프로젝트 명칭은 생산 화면의 식별 기준으로 유지하고 기존 프로젝트 ID로 구분합니다. 해당 컬러·프로젝트의 차수가 여러 개면 선택을 요청합니다. 탭 안에서 컬러나 생산 오더를 바꾸면 다른 관련 탭에도 반영하며, 미저장 내용이 있으면 먼저 저장하거나 취소합니다. 이 과정에서 스타일의 기존 프로젝트 연결이나 과거 차수의 프로젝트를 바꾸지 않습니다.

메인 생산의 **선택한 프로젝트 생산 현황**은 해당 프로젝트·컬러·차수의 오더·확정 입고·미입고 잔량을 표시합니다. 아래 사이즈 표는 기존 구조대로 해당 컬러의 전체 누적 출고·입고 입력에 사용합니다. 프로젝트별 출고 배분 기록이 없으면 전체 출고를 프로젝트별 수량으로 추정하지 않습니다. 업체 계정에 공개되지 않는 차수 입고 기록은 전체 컬러 입고 수량으로 대신 표시하지 않습니다.

## 보존 범위

프로젝트·스타일·컬러·생산 차수 ID, 원본 출고 기록, PO 발송·업체 회신·본사 승인, 부분 납기, 기존 입고·무효 이력, 마감·을지 확정 금액과 변경 이력은 유지합니다. 검사 업체와 FA팀의 기존 조회 범위도 유지합니다. 기존 고정 을지의 셀 위치·수식·VAT·합계는 변경하지 않습니다.

실제 실행한 검증 결과는 [테스트 결과](TEST_RESULTS.md)에 기록합니다.
