# 생산 조건 협의·승인 안내

2026-10-29 기준 검증 브랜치: `codex/production-conditions-approval-20261028`.

2026-10-30 화면 개선으로 PO 작성·발송이 이 협의 화면에 통합되었습니다. 생산 차수 화면의 본사 검토 단가 입력과 원부자재 세부 컨펌은 [생산 업무 개선 안내](PRODUCTION_WORKFLOW_UPDATE.md)를 함께 참고하세요.

이 문서는 PR 검토 대상인 새 생산 절차를 설명합니다. 이번 변경의 SQL 013~015는 운영 Supabase에 적용하지 않았으며, 운영 Vercel 배포나 실제 업체 대상 시험 메일 발송도 수행하지 않습니다. 최종 자동 시험 결과는 [테스트 결과](TEST_RESULTS.md)를 확인하세요. 아래 절차는 별도 검증 환경에서 먼저 확인한 뒤 운영 적용을 별도로 검토합니다.

## 달라지는 생산 절차

업체가 입력한 납기와 단가는 제안으로 기록됩니다. 본사 최종 승인 시에만 생산이 시작되며, 승인 전 실입고와 마감 확정은 서버에서도 차단합니다. 기존 **업체 납기·동의** 탭의 새 이름은 **생산 조건 협의·승인**입니다.

| 상태 | 다음 업무 |
| --- | --- |
| PO 발송 대기 | 본사가 차수에 PO를 연결하고 내용을 확인한 뒤 발송 |
| 업체 회신 대기 | 배정 업체가 납기·단가·생산 가능 여부와 수량 확인 제출 |
| 본사 최종 승인 대기 | 본사가 업체 제안을 검토하며 생산은 시작되지 않음 |
| 업체 재협의 요청 | 업체가 수정 조건을 제출하고 본사가 다시 검토 |
| 생산 승인 완료 / 생산 진행 중 | 승인된 조건에 따라 생산·차수 실입고·마감 진행 |
| 발주 거절 | 생산 시작을 막고 발주·회신·검토 이력 보존 |
| 마감 확정 | 확정 당시 단가·입고·금액·승인 근거 보존 |

공장 배정이 바뀐 발주는 별도로 표시합니다. 이전 업체의 발주를 새 공장에 임의로 이어 붙이지 않습니다.

## 본사에서 발주하기

1. 본사·관리자 계정으로 품번 상세의 **생산 차수·마감 → 생산 차수 추가**를 엽니다.
2. 프로젝트, 컬러, 차수명, 사이즈별 오더 수량과 본사 요청 납기를 입력하고 저장합니다. 메인 생산의 누적 수량과 차수별 수량은 별도 집계입니다.
3. **생산 조건 협의·승인**에서 **프로젝트 코드 · 공식 명칭**과 해당 생산 차수를 선택하고 **생산 방식·검토 기준 설정**을 엽니다.
4. **완사입** 또는 **임가공 (CMT)**을 선택합니다. 필요하면 본사 내부 검토 단가를 입력하고 사유와 함께 **생산 조건 기준 저장**을 누릅니다.
5. **이 차수 PO 작성**에서 수신인, 납기, 프로젝트·전체 품번·컬러·차수·사이즈별 수량·생산 방식과 관련 첨부를 확인합니다. 초안을 저장하면 해당 차수에 연결됩니다.
6. 같은 화면 아래 **PO 메일 및 발송 이력**에서 Outlook 계정·수신인·메일 내용을 확인하고 **PO 메일 발송 → 발송 확인**으로 명시적으로 발송합니다. 초안 저장이나 차수 연결만으로는 메일을 보내지 않습니다.

단가 입력은 다음 세 가지로 구분합니다.

| 단가 | 입력·조회 범위 | 사용처 |
| --- | --- | --- |
| 본사 내부 검토 단가 | 본사만 입력·조회 | 업체 제안과 비교하는 내부 기준 |
| 업체 제안 생산 단가 | 배정 업체가 제출, 본사가 검토 | 완사입은 완제품 단가, 임가공은 CMT 단가 |
| 본사 최종 승인 단가 | 본사가 최종 승인할 때 확정 | 생산 차수 `unit_cost`, 이후 실제 입고와 제품 을지·마감 |

본사 내부 검토 단가는 **생산 차수·마감 → 본사 검토 단가 입력·수정**에서도 같은 값으로 저장할 수 있습니다. 최종 승인 전 검토 기준이며 확정 생산 단가와 마감 금액을 직접 덮어쓰지 않습니다.

미입력과 0원은 다릅니다. 내부 기준가는 공란으로 둘 수 있지만 업체 제안과 최종 승인은 단가를 명시해야 하며, 0원도 명시적인 입력값으로 보존합니다. 본사 내부 기준가·마진·다른 업체 정보는 공장에 제공하지 않습니다. 별도의 가공·품질 작업 단가는 [가공·품질 단가 가이드](PROCESSING_PRICES.md)를 따릅니다.

## 업체에서 회신하기

1. 승인·활성 상태이며 해당 공장에 배정된 업체 계정으로 접속합니다.
2. 품번 상세의 **생산 조건 협의·승인**에서 프로젝트·생산 차수를 선택합니다.
3. 연결된 발송 PO, 전체 품번·컬러, 수량, 본사 요청 납기와 생산 방식을 확인합니다.
4. **생산 조건 회신**에서 예상 납기일, 제안 단가와 생산 가능 여부를 입력합니다. PO 수량 확인과 생산 조건 동의에도 체크합니다. 업체 의견·납기 지연 사유·단가 변경 사유는 필요할 때 입력합니다.
5. **생산 조건 제출**을 누르면 **본사 최종 승인 대기**가 됩니다. 업체 제출만으로 생산이 시작되지 않습니다.

수정 요청을 받으면 **수정 조건 재제출**에서 새 제안을 제출합니다. 이전 제출 내용과 본사 요청 사유는 협의 이력으로 남습니다. 업체는 본사 내부 기준가와 본사가 확정한 단가를 수정할 수 없습니다.

## 본사에서 검토·승인하기

본사는 요청·검토 기준, 업체 제안과 최종 승인 조건을 같은 표에서 비교합니다. 요청 납기가 2026-11-11이고 제안 납기가 2026-11-30이면 **19일 지연**으로 표시합니다. 본사 화면에서는 내부 기준가 대비 제안 단가 차이도 확인합니다.

- **최종 승인**: 최종 납기·최종 단가와 사유를 입력하고 **최종 승인 및 생산 시작**을 누릅니다. 승인 담당자·시각, 업체 제안·회신 담당자, PO 발송 근거, 프로젝트·차수·컬러·수량·생산 방식을 확정 기록으로 보존합니다.
- **수정 요청**: 재협의할 사유를 남기고 **수정 요청 전달**을 누릅니다. 업체 재제출 후 다시 검토합니다.
- **발주 거절**: 사유와 함께 **발주 거절 확정**을 누릅니다. 생산을 시작하지 않고 기존 이력을 남깁니다.

다른 사용자가 먼저 수정하면 저장을 거부하고 작성 중인 값을 유지합니다. 최신 정보를 확인한 뒤 다시 검토해야 합니다. 업체 회신 후 발주 조건이 달라진 경우에도 이전 회신을 새 조건에 임의 적용하지 않습니다.

## 발송한 PO가 생산 차수에 연결되지 않았을 때

**생산 조건 협의·승인 → PO 메일 및 발송 이력 → 전체 PO 이력**의 **생산 차수 미연결**은 메일 발송과 생산 차수 연결이 별도라는 뜻입니다. 이미 보낸 메일을 다시 보내는 절차가 아닙니다.

1. **생산 차수·마감**에서 연결할 차수를 PO 미연결 상태로 먼저 등록합니다.
2. **생산 조건 협의·승인 → 전체 PO 이력**의 발송 기록에서 **기존 생산 차수에 연결**을 누르고 차수를 선택합니다.
3. 실제 발송한 메일·첨부 발주서와 화면의 프로젝트·전체 품번·컬러·공장·사이즈별 수량을 비교합니다.
4. **발송 문서 생산 조건 확인**과 연결 사유를 입력합니다. 이전 PO에 비교용 원본 정보가 없으면 **기존 PO 비교 정보 미등록 확인**도 필요합니다.
5. 메인 누적 수량과 차수 수량이 다르면 집계 기준을 확인하고 **수량 집계 범위 차이 확인**에 체크합니다. 자동으로 수량을 덮어쓰지 않습니다.
6. **확인한 생산 차수에 연결**을 누릅니다. 연결 후 협의 화면을 다시 불러오며 메일은 재발송하지 않습니다.

새 PO 작성 때 보존하는 비교 정보는 발송 문서를 사람이 확인하는 절차를 돕는 자료입니다. 메일 본문과 첨부 내용을 자동으로 해석해 일치한다고 판정하지 않습니다. 제목이 비슷한 PO를 자동 연결하지 않으며, 서로 다른 프로젝트·컬러·업체를 연결하거나 PO를 중복 연결하는 요청은 서버에서 거부합니다.

## 최종 승인 후 조건을 바꿀 때

승인된 차수의 단가·납기·수량·생산 방식은 일반 수정으로 덮어쓰지 않습니다. 실제 입고와 확정 마감 금액에도 소급 적용하지 않습니다.

1. 승인된 차수에서 **승인 조건 변경 요청**을 열고 사유를 입력한 뒤 **조건 변경 요청 기록**을 누릅니다.
2. 본사가 **생산 차수·마감 → 생산 차수 추가**에서 별도 차수를 직접 등록합니다. 기존 차수를 자동 복제하지 않습니다. 추가 생산과 정정 생산 중 어떤 범위인지 판단하고 그 범위의 수량을 명시합니다.
3. 협의 화면의 **변경 요청에 새 차수 연결**을 열고 변경 요청과 **재승인할 새 생산 차수**를 선택합니다. 기존 승인 차수·새 차수·메인 누적 오더를 비교하고 **새 차수 오더 수량 및 집계 범위 확인** 후 **변경 요청과 새 차수 연결**을 누릅니다.
4. 새 차수의 PO와 업체 회신을 준비하고 본사가 다시 최종 승인합니다.

원래 차수의 승인·입고·마감은 그대로 남습니다. 새 차수는 별도 실적과 금액을 생성하므로 동일 물량을 중복 입고·청구하지 않도록 업무 범위를 확인해야 합니다.

## 기존 데이터와 보안

- 014 최초 적용 시 이미 생산 시작이 기록된 차수만 한 번 수집해 **기존 프로세스 승인 기록**으로 구분합니다. 재실행으로 이후 차수를 이전 프로세스로 바꾸지 않습니다. 기존 입고·마감 스냅샷을 재계산하거나 단가를 일괄 변경하지 않습니다.
- 기존 방식의 업체 동의 RPC와 별도 생산 시작 RPC는 새 차수의 본사 승인 우회 수단으로 사용할 수 없습니다.
- 조건 원문·내부 기준가·협의·승인·변경 요청 이력은 전용 테이블에 저장하고 직접 조회·수정을 제한합니다. 외부 공장은 배정된 발주의 공개 결과만 서버 RPC로 받습니다.
- 승인·조건 제출·수정 요청·거절·PO 연결은 서버에서 현재 계정의 승인·활성·공장 배정과 버전을 확인합니다. 화면 버튼 비활성화에만 의존하지 않습니다.
- 마감은 최종 승인 단가와 해당 차수의 실제 입고를 사용하며, 조회용 누적 수량을 임의로 차수 입고로 이관하지 않습니다.

## 검증 환경 준비와 SQL 순서

운영 데이터베이스를 초기화하거나 기존 008 SQL을 교체하지 않습니다. 별도 Supabase 검증 프로젝트에서 먼저 확인합니다.

| 순서 | 파일 | 추가 범위 |
| --- | --- | --- |
| 선행 | 001~012 | 기존 계정·스타일·생산·PO·Outlook 구조 |
| 013 | [013_processing_unit_prices.sql](../supabase/migrations/013_processing_unit_prices.sql) | 컬러·가공 작업별 단가와 이력 |
| 014 | [014_production_conditions.sql](../supabase/migrations/014_production_conditions.sql) | 업체 제안, 본사 검토·최종 승인, 기존 생산 구분, 변경 요청 |
| 015 | [015_production_po_link.sql](../supabase/migrations/015_production_po_link.sql) | PO 비교 원본, 확인 연결과 연결 이력 |

아직 적용하지 않은 파일을 **013 → 014 → 015** 순서로 검토·적용합니다. 최초 검증 시 운영과 구분되는 프로젝트의 공개 URL·anon 키를 사용하고 예시 시드나 초기화 SQL을 운영 데이터에 적용하지 않습니다. 적용 전후 기존 생산 차수·입고·마감 스냅샷·PO 건수와 값을 비교합니다. 앱만 먼저 바꾸거나 일부 SQL만 적용했을 때는 기능 준비 안내가 표시될 수 있습니다.

기존 Outlook 연동의 앱 ID·테넌트 ID와 발신자별 연결 방식은 유지하며 새 비밀키를 요구하지 않습니다. 별도 검증 주소에서 실제 OAuth 인증까지 시험할 경우에는 해당 주소의 `/outlook-callback.html`을 Microsoft 앱의 SPA 리디렉션 URI에 등록해야 합니다. 검증용 Supabase Auth URL과 검증용 메일 함수의 허용 출처도 검증 주소에 맞춰 별도로 설정합니다. 운영 계정·운영 발송 함수를 그대로 검증 환경에 연결하지 않습니다. 세부 연결 방식은 [Outlook 가이드](OUTLOOK_SETUP.md)를 따릅니다.

운영 적용 전에는 PR의 최종 시험 결과와 변경 SQL을 검토하고, 별도 환경에서 관리자·본사·두 공장의 회신·수정 요청·승인·입고·마감 및 모바일 화면을 확인합니다. 운영 SQL 실행과 배포는 이 개발 작업에 포함하지 않습니다.
