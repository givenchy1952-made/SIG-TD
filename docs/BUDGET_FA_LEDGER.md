# 예산·을지 누적

왼쪽 메뉴의 **예산·을지 누적**에서 발주 예산, 원가, 생산 마감 을지, 결제 상태를 확인합니다. 입고현황·생산 관리와 분리된 메뉴입니다. 프로젝트 명칭·프로젝트 코드·컬러 포함 스타일코드·시즌·업체를 복수 선택할 수 있으며, 선택한 조건으로 화면과 다운로드를 함께 제한합니다.

## 권한과 운영 적용

본사 관리자·직원은 원가·예산한도·결제 상태·발생 사유를 입력합니다. **FA팀**은 이 메뉴만 열람하고 파일을 내려받습니다. FA팀에는 스타일·생산·PO·사진·원본 오더 파일·다른 사용자의 계정 정보를 제공하지 않습니다. 협력업체에는 예산 메뉴를 제공하지 않습니다.

기존 SQL001~021 이후 다음 네 파일을 순서대로 Supabase SQL Editor에서 수동 실행합니다. 이전 SQL을 수정하거나 시드를 실행하지 않습니다.

1. `supabase/migrations/022_finance_role.sql`: FA팀 역할과 생산 접근 제한.
2. `supabase/migrations/023_budget_fa_ledger.sql`: 예산 자료·결제 상태·사유·변경 이력과 전용 조회/저장 함수.
3. `supabase/migrations/024_budget_order_metadata.sql`: 새 오더 업로드의 브랜드·발주 요청일·JOOR GB·ADER KOR 정보를 보관합니다. 기존 원본은 재작성하지 않으며, 이전 업로드에 없던 열은 필요할 때 해당 오더 파일을 다시 확인해 적용합니다.

4. `supabase/migrations/025_budget_cost_import.sql`: 원가계산서 일괄 업로드, 원본 행 연결·중복 방지·동시 수정 확인 및 원가 금액 소수 6자리 계산. 024까지 이미 적용했다면 025만 추가합니다.

웹 코드를 배포한 뒤 FA 담당자는 일반 회원가입을 진행합니다. 관리자가 **사용자 · 기본 설정 → 구성원 권한 수정 → 역할 FA팀 → 업무 접근 승인·활성 계정**을 설정합니다. 새 역할을 추가해도 기존 사용자의 역할을 자동 변경하지 않습니다. SQL이 적용되지 않은 상태에서는 저장을 허용하거나 성공으로 표시하지 않습니다.

## 발주요청세부와 원가

프로젝트 코드는 본사 내부 예산 관리 코드이고 프로젝트 명칭은 생산 협의 명칭입니다. 두 값을 합치지 않습니다. 예산 코드만 **프로젝트 코드+컬러 포함 스타일코드**에서 공백을 제거해 생성합니다. 예: `SIGNIFICANT-2026FY-RPQ-46024BP06FYKT0703OT`.

발주요청세부의 A~L은 등록된 오더·프로젝트·생산 차수의 확인 가능한 정보로 구성합니다. 누적 차수가 있으면 차수 오더를 사용하고 현재 스타일의 같은 수량을 다시 더하지 않습니다. 원본 자료에 없는 JOOR/ADER 수량이나 날짜를 추정하지 않습니다.

발주표 **O열은 장당 생산 원가**, **M열은 장당 생산 원가 × 생산 수량(J TTL)**입니다. 첨부 최종 예산 파일의 **U 생산 예산·W 생산 원가**와 같은 방식으로 계산합니다. 업로드한 일반 원가 항목은 변동단가(R)가 있으면 우선 사용하고, 없으면 단가(Q)에 요척량(S)을 곱해 장당 원가를 합산합니다. 명시적 변동단가 0원도 우선합니다.

종류가 **공용비용**인 항목은 해당 금액을 생산 수량에 배분하여 총예산에 한 번만 반영합니다. 기존 직접 입력한 원가 금액은 총 공급가액으로 입력했던 의미를 유지하며 수량을 다시 곱하지 않습니다. 이런 총액은 장당 생산 원가에 수량으로 나눠 포함합니다. 원가 미등록과 명시적으로 입력한 0원은 구분합니다. 같은 프로젝트·품번의 복수 생산 차수는 생산 수량을 합산한 뒤 계산합니다.

**N 사후원가 확인은 발주표에서 제거**했습니다. Excel은 M/O 열 위치를 유지하도록 N을 빈 열로 숨기며, CSV에도 N 확인 내용은 넣지 않습니다. M은 O×J 수식과 계산 결과, O는 장당 원가를 내보냅니다. 사후 원가 기록과 과거 변경 이력은 유지하고, 사후 원가 미등록만으로 미종결 처리하지 않습니다. 대시보드·업체별 현황·시즌 한도 잔액·초과/미종결 금액도 같은 생산 예산으로 집계합니다.

이 계산 수정은 추가 SQL 없이 웹 배포 후 저장된 원가를 다시 조회하면 적용됩니다. 원가 파일을 다시 업로드하거나 생산 기록을 재작성할 필요가 없습니다.

### 원가계산서 파일 업로드

**예산·을지 누적 → 원가계산서 → 원가계산서 업로드**에서 제공된 `ADER_SIG_2026_신규_OUTER.xlsx`와 같은 형식의 .xlsx 파일을 선택합니다. 15행 제목 아래 값이 있는 항목을 읽고 참조 목록 시트와 빈 양식 행은 제외합니다. 미리보기에서 연결과 금액을 확인하고 업로드 사유를 입력한 뒤 **검증된 원가 적용**을 누릅니다. 파일 하나의 적용은 전체 성공 또는 전체 취소입니다.

| 원본 파일 | 사이트 원가표 및 다운로드 |
| --- | --- |
| B 프로젝트 코드 + C SKU NO. | 등록된 발주 A 프로젝트 코드 + D 컬러 포함 스타일코드와 함께 일치해야 연결 |
| 등록된 발주 정보 | A 프로젝트 코드, C 프로젝트 명칭, D 스타일코드, E 브랜드, F 시즌, G 생산구분, H 발주 코드 |
| 원본 D~O | 원가표 I~T 순서 그대로 연결 |
| 원본 L 단가 × N 요척량 | 원가표 U = Q × S, 발주수량을 추가로 곱하지 않음 |

원가표 B 예산 코드는 A+D의 공백 없는 조합입니다. 업로드 원가는 사전 원가로 등록하며 기존 사후 원가와 직접 입력한 원가는 유지합니다. 단가는 소수 2자리, 요척량은 4자리, 계산 금액은 6자리까지 보존합니다. 필수 단가·요척량이 비어 있으면 0으로 바꾸지 않고 적용을 막습니다. 명시한 0원은 유효합니다.

동일 프로젝트 코드·SKU가 여러 프로젝트에 연결되면 미리보기에서 프로젝트를 직접 선택합니다. 기존 발주가 없는 코드는 원가를 만들지 않습니다. 새 프로젝트·스타일·업체를 자동 생성하지 않습니다. 등록되지 않은 원가 업체는 원본 업체명을 보존하고 그 이름으로 예산 업체 필터와 집계에 표시합니다. 필요하면 나중에 등록된 업체로 연결할 수 있습니다.

같은 파일의 같은 시트·행은 기존 업로드 원가를 갱신하며, 내용이 같으면 중복 제외합니다. 내용이 같은 파일은 이름을 바꿔도 다시 누적하지 않습니다. **내용을 수정할 때는 최초 파일명·시트명·항목 행 위치를 유지**해 주세요. 파일명과 내용을 동시에 바꾸거나 행을 이동하면 연결 확인이 필요하며 중복 가능성이 있는 적용은 막습니다. 수정 파일에서 빠진 기존 행은 자동 삭제하지 않습니다. 더 이상 사용하지 않을 원가는 해당 항목 수정에서 제외합니다.

Excel 수식 셀은 Excel이 저장한 계산 결과를 읽습니다. 결과가 없는 수식은 원본 파일을 Excel에서 다시 계산·저장한 뒤 업로드합니다. 업로드 화면은 현재 대시보드 필터와 관계없이 선택한 시트 전체를 검사하며, 완료 후 전체 원가 목록으로 돌아갑니다. 파일명·시트·원본 행을 연결 근거로 표시합니다. 원본 통합문서 자체를 다른 계정에 공개하지 않습니다.

업로드 원가를 직접 수정할 때도 U는 Q×S로 자동 계산합니다. 일반 수동 원가의 직접 금액 입력 방식은 유지합니다. 업로드 원가의 Excel U열에는 Q×S 수식과 계산 결과가 들어가며, FA팀이 내려받을 때도 같습니다.

## FA을지 누적과 결제

생산 차수의 **마감 확정 스냅샷**을 기준으로 생산 을지를 누적합니다. 생산이 진행 중이거나 마감이 확정되지 않은 기록은 확정 을지 금액으로 간주하지 않습니다. 새 화면은 기존 생산·가공·품질 을지와 과거 마감 금액을 수정하지 않습니다.

새 FA 양식의 A~U는 지급일, 품의서 번호, 업체, 발주날짜, 프로젝트 코드, 프로젝트+업체 코드, 스타일코드, ERP 계정과목, 품목, 단가, 요척, 오더수량, 입고수량, 단위, 공급가액, VAT, 합계, 담당자, 산출근거, 분할 결제, 결제 상태입니다. 엑셀은 3행 머리글·4행 자료를 사용하고 O=M×J, P=O×10%, Q=O+P 수식을 제공합니다. U열은 **결제/미결제** 선택입니다.

본사에서 실제 지급을 확인한 후 결제 상태와 지급일·사유를 저장합니다. 이 기능은 지급 여부를 기록하며 은행 송금을 실행하지 않습니다. 기존 생산 라인의 결제 표시를 새 결제 기록으로 자동 전환하지 않습니다. 금액·수량 등 근거 자료가 바뀌면 과거 결제 상태를 새 금액에 그대로 적용하지 않습니다.

## 대시보드와 예외 내역

발주 예산, 결제한 지출, 앞으로 지급할 예산, 확정 을지 중 미결제 금액을 구분합니다. 예산·지출 비교는 **공급가액 기준**이며 VAT와 지급 합계는 별도로 확인합니다. 원가 미등록 항목이 있으면 집계 누락 여부를 함께 표시합니다. 시즌 예산한도는 본사가 직접 입력하며 첨부 파일의 과거 금액을 기본값으로 사용하지 않습니다.

초과 내역은 예산보다 지출이 많은 항목과 차액을 보여 줍니다. 미종결 내역에는 남은 결제·입고·원가 확인 등 종결하지 못한 사유를 표시합니다. 본사는 두 목록의 발생 사유를 기록하고 변경 이력을 남깁니다. 파일의 과거 95% 종결 또는 설명과 불일치하는 초과 기준을 미지급 금액을 없애는 기준으로 사용하지 않습니다.

## 다운로드

Excel은 요청한 6개 시트의 열을 사용해 새로 생성합니다. 깨진 외부 참조와 과거 회사 자료가 들어 있는 피벗 캐시를 복사하지 않습니다. FA 고정 열·수식·결제 드롭다운을 유지하고 화면의 최종 조건과 같은 범위를 내려받습니다. CSV도 같은 범위와 값을 사용합니다.
