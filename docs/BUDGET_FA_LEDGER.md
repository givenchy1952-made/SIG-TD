# 예산·을지 누적

왼쪽 메뉴의 **예산·을지 누적**에서 발주 예산, 원가, 생산 마감 을지, 결제 상태를 확인합니다. 입고현황·생산 관리와 분리된 메뉴입니다. 프로젝트 명칭·프로젝트 코드·컬러 포함 스타일코드·시즌·업체를 복수 선택할 수 있으며, 선택한 조건으로 화면과 다운로드를 함께 제한합니다.

## 권한과 운영 적용

본사 관리자·직원은 원가·예산한도·결제 상태·발생 사유를 입력합니다. **FA팀**은 이 메뉴만 열람하고 파일을 내려받습니다. FA팀에는 스타일·생산·PO·사진·원본 오더 파일·다른 사용자의 계정 정보를 제공하지 않습니다. 협력업체에는 예산 메뉴를 제공하지 않습니다.

기존 SQL001~021 이후 다음 세 파일을 순서대로 Supabase SQL Editor에서 수동 실행합니다. 이전 SQL을 수정하거나 시드를 실행하지 않습니다.

1. `supabase/migrations/022_finance_role.sql`: FA팀 역할과 생산 접근 제한.
2. `supabase/migrations/023_budget_fa_ledger.sql`: 예산 자료·결제 상태·사유·변경 이력과 전용 조회/저장 함수.
3. `supabase/migrations/024_budget_order_metadata.sql`: 새 오더 업로드의 브랜드·발주 요청일·JOOR GB·ADER KOR 정보를 보관합니다. 기존 원본은 재작성하지 않으며, 이전 업로드에 없던 열은 필요할 때 해당 오더 파일을 다시 확인해 적용합니다.

웹 코드를 배포한 뒤 FA 담당자는 일반 회원가입을 진행합니다. 관리자가 **사용자 · 기본 설정 → 구성원 권한 수정 → 역할 FA팀 → 업무 접근 승인·활성 계정**을 설정합니다. 새 역할을 추가해도 기존 사용자의 역할을 자동 변경하지 않습니다. SQL이 적용되지 않은 상태에서는 저장을 허용하거나 성공으로 표시하지 않습니다.

## 발주요청세부와 원가

프로젝트 코드는 본사 내부 예산 관리 코드이고 프로젝트 명칭은 생산 협의 명칭입니다. 두 값을 합치지 않습니다. 예산 코드만 **프로젝트 코드+컬러 포함 스타일코드**에서 공백을 제거해 생성합니다. 예: `SIGNIFICANT-2026FY-RPQ-46024BP06FYKT0703OT`.

발주요청세부의 A~L은 등록된 오더·프로젝트·생산 차수의 확인 가능한 정보로 구성합니다. 누적 차수가 있으면 차수 오더를 사용하고 현재 스타일의 같은 수량을 다시 더하지 않습니다. 원본 자료에 없는 JOOR/ADER 수량이나 날짜를 추정하지 않습니다.

사전 원가 항목의 명시한 금액을 합산해 M열 생산 예산을 계산합니다. N열에는 원가 연결 여부를 표시하고, O열에는 생산 예산을 발주 수량으로 나눈 단가를 표시합니다. 원가 미등록과 명시적으로 입력한 0원은 구분합니다.

**실제 원가계산서 예시는 아직 받지 않았습니다.** 현재 원가 항목과 사전·사후 금액을 직접 등록할 수 있습니다. 파일의 원가 U열에 검증 가능한 계산 예시가 없으므로 단가·요척·수량을 임의로 곱하지 않습니다. 추후 제공받는 원가계산서의 열과 산식을 확인한 뒤 자동 가져오기를 연결해야 합니다.

## FA을지 누적과 결제

생산 차수의 **마감 확정 스냅샷**을 기준으로 생산 을지를 누적합니다. 생산이 진행 중이거나 마감이 확정되지 않은 기록은 확정 을지 금액으로 간주하지 않습니다. 새 화면은 기존 생산·가공·품질 을지와 과거 마감 금액을 수정하지 않습니다.

새 FA 양식의 A~U는 지급일, 품의서 번호, 업체, 발주날짜, 프로젝트 코드, 프로젝트+업체 코드, 스타일코드, ERP 계정과목, 품목, 단가, 요척, 오더수량, 입고수량, 단위, 공급가액, VAT, 합계, 담당자, 산출근거, 분할 결제, 결제 상태입니다. 엑셀은 3행 머리글·4행 자료를 사용하고 O=M×J, P=O×10%, Q=O+P 수식을 제공합니다. U열은 **결제/미결제** 선택입니다.

본사에서 실제 지급을 확인한 후 결제 상태와 지급일·사유를 저장합니다. 이 기능은 지급 여부를 기록하며 은행 송금을 실행하지 않습니다. 기존 생산 라인의 결제 표시를 새 결제 기록으로 자동 전환하지 않습니다. 금액·수량 등 근거 자료가 바뀌면 과거 결제 상태를 새 금액에 그대로 적용하지 않습니다.

## 대시보드와 예외 내역

발주 예산, 결제한 지출, 앞으로 지급할 예산, 확정 을지 중 미결제 금액을 구분합니다. 예산·지출 비교는 **공급가액 기준**이며 VAT와 지급 합계는 별도로 확인합니다. 원가 미등록 항목이 있으면 집계 누락 여부를 함께 표시합니다. 시즌 예산한도는 본사가 직접 입력하며 첨부 파일의 과거 금액을 기본값으로 사용하지 않습니다.

초과 내역은 예산보다 지출이 많은 항목과 차액을 보여 줍니다. 미종결 내역에는 남은 결제·입고·원가 확인 등 종결하지 못한 사유를 표시합니다. 본사는 두 목록의 발생 사유를 기록하고 변경 이력을 남깁니다. 파일의 과거 95% 종결 또는 설명과 불일치하는 초과 기준을 미지급 금액을 없애는 기준으로 사용하지 않습니다.

## 다운로드

Excel은 요청한 6개 시트의 열을 사용해 새로 생성합니다. 깨진 외부 참조와 과거 회사 자료가 들어 있는 피벗 캐시를 복사하지 않습니다. FA 고정 열·수식·결제 드롭다운을 유지하고 화면의 최종 조건과 같은 범위를 내려받습니다. CSV도 같은 범위와 값을 사용합니다.
