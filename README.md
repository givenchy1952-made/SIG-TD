# SIG SAMPLE MANAGEMENT

FIVE SPACE / SIG의 샘플 진행, 메인 생산, 일정 및 업체 결제 마감을 함께 관리하는 React + TypeScript 웹 애플리케이션입니다. 한국어 UI를 기본으로 제공하며 Tailwind CSS, Supabase Auth·Postgres·Realtime·Storage를 사용합니다.

이 저장소의 기존 파일은 `README.md` 한 개뿐이었습니다. 기존 SIG HTML 및 프로젝트는 포함되어 있지 않아 과거의 빈 화면 오류를 재현하거나 기존 코드를 재사용할 수 없었습니다. 이번 버전은 실행 진입점과 데이터 계층을 새로 구현했습니다. 연결 정보 누락·접근 거부·저장 충돌은 안내 메시지로 처리합니다.

## 빠른 실행

Node.js 22 이상과 npm을 권장합니다. 개발 환경에서 다음 명령을 실행하세요.

```bash
npm ci
cp .env.example .env.local
npm run dev
```

터미널에 표시된 로컬 개발 주소로 접속합니다. Supabase URL·키를 비워 두면 **개발 서버에서 체험 모드**를 사용할 수 있습니다. 처음 접속하면 예시 데이터 대시보드가 열립니다. 로그아웃 후에는 로그인 화면의 체험 시작 버튼으로 다시 들어갈 수 있습니다. 예시 스타일·공장·담당자·수량은 실제 업무 데이터가 아닙니다.

체험 모드는 브라우저 저장소를 사용합니다. 같은 브라우저의 탭 사이에는 변경 사항을 반영하고 버전 충돌을 감지하지만, 서로 다른 컴퓨터·브라우저·사용자 간 공유는 지원하지 않습니다. 체험 계정의 역할 선택은 권한 화면을 확인하기 위한 기능이며 실제 사용자 인증이 아닙니다. 첨부파일은 해당 브라우저의 IndexedDB에 저장됩니다.

공유 시안 배포에서 체험 모드를 공개하려면 `VITE_ENABLE_DEMO=true`를 명시해야 합니다. 이 경우 누구나 예시 환경을 열 수 있으므로 실제 업무·개인정보를 넣지 마세요. 운영 배포에서는 `VITE_ENABLE_DEMO=false`를 유지하고 Supabase를 연결하세요. 개발 서버와 localhost를 제외한 운영 배포에서 연결 정보와 체험 허용 설정이 모두 없으면 설정 안내 화면을 표시합니다.

## Supabase 실제 연결

1. 새 Supabase 프로젝트는 SQL Editor에서 [001_initial.sql](supabase/migrations/001_initial.sql) → [002_style_images.sql](supabase/migrations/002_style_images.sql) → [003_operations.sql](supabase/migrations/003_operations.sql) → [004_settlement_terms.sql](supabase/migrations/004_settlement_terms.sql) → [005_workflow_refinements.sql](supabase/migrations/005_workflow_refinements.sql)을 **순서대로 각각 한 번** 실행합니다. **001~004 적용이 끝난 기존 프로젝트는 005만 한 번 실행하세요. 이미 적용한 SQL은 다시 실행하지 않습니다.** 005는 프로젝트 코드·명칭 분리, 가져오기 중 스타일·프로젝트 등록, 반차·반반차, 품질 검사·치수표 저장을 추가합니다. 기존 샘플·수량·출고 이력은 초기화하지 않습니다.
2. 아래 환경변수를 `.env.local` 또는 호스팅 환경에 입력합니다.
3. Supabase Auth의 **Site URL**과 **Redirect URLs**에 실제 접속 주소를 등록합니다. 로컬 개발 주소와 배포 주소가 다르면 각각 추가하세요. 운영에서는 이메일 확인을 활성화하고, 팀 정책에 맞는 이메일 발송 설정을 확인하세요.
4. 앱을 다시 실행하거나 다시 빌드한 후 첫 관리자 계정으로 회원가입하고 이메일 확인을 완료합니다. 첫 가입은 승인 대기 상태입니다.
5. 아래의 첫 관리자 설정 SQL을 Supabase SQL Editor에서 실행합니다. 그다음 다시 로그인하거나 화면을 새로고침합니다.
6. 관리자 화면에서 공장·프로젝트를 등록합니다. 다른 담당자가 회원가입하면 역할·소속 공장을 지정하고 승인합니다. 본사 담당 공장은 별도 복수 배정할 수 있습니다. 003에는 사용자가 제공한 라벨 23종·자수 33종 목록이 포함됩니다. 종류명·구분은 고정하며 관리자는 기존 종류의 사용 여부만 바꿉니다. 실제 작업·수량을 임의로 만들지 않습니다.

```dotenv
VITE_SUPABASE_URL=https://YOUR_PROJECT_REF.supabase.co
VITE_SUPABASE_ANON_KEY=YOUR_PUBLIC_ANON_OR_PUBLISHABLE_KEY
VITE_ENABLE_DEMO=false
```

`VITE_` 값은 클라이언트 번들에 포함됩니다. 공개 `anon` 또는 `publishable` 키만 사용하세요. `service_role`, Supabase secret 키, 데이터베이스 비밀번호는 브라우저 환경변수에 넣지 마세요. 실제 접근 제한은 데이터베이스의 RLS와 RPC에서 적용합니다.

`VITE_SUPABASE_URL`에는 `https://프로젝트주소.supabase.co` 형태의 **프로젝트 기본 주소**를 입력하세요. Data API의 `/rest/v1/` 주소를 입력한 경우 앱이 기본 주소로 보정하여 가입·로그인·파일 요청에 사용합니다. 지원하지 않는 경로·쿼리·접속 정보는 설정 오류로 안내합니다. 이전 버전의 가입 화면에서 `Invalid path specified in request URL`이 발생하면 이 설정을 확인하고 최신 코드를 다시 배포하세요. Vercel에서 환경변수를 바꾼 경우에도 **Redeploy**가 필요합니다.

네트워크 제한이 있는 환경에서는 해당 Supabase 프로젝트 호스트에 대한 HTTPS와 WebSocket 연결이 필요합니다. 선택 사항인 `supabase/seed.sql`은 EXAMPLE 표시가 있는 공장·프로젝트 기준 정보를 추가하고, 첫 관리자가 이미 있으면 명시적으로 표시된 예시 스타일 1개를 추가합니다. 실제 사용자·비밀번호는 만들지 않습니다. 운영 프로젝트에는 필요할 때만 검토 후 적용하세요. 브라우저 예시 스타일은 `src/lib/seed.ts`에 있으며 클라우드로 자동 이관하지 않습니다.

이 저장소에는 실제 Supabase 계정·키가 제공되지 않았습니다. 실제 Auth, 원격 저장, Storage, 서로 다른 사용자 간 Realtime 동작은 프로젝트 연결 후 확인해야 합니다.

### 이메일 인증 후 localhost로 이동하거나 링크가 만료된 경우

Supabase의 **Authentication → URL Configuration**에서 **Site URL**을 실제 프로그램의 고정 운영 주소로 바꾸고 **Redirect URLs**에도 같은 주소를 추가한 뒤 저장하세요. 예를 들어 운영 주소가 `https://sig-td.vercel.app`이면 두 곳에 이 주소를 등록합니다. 기본값인 `http://localhost:3000`은 운영 접속 주소로 사용하지 않습니다. 미리보기 배포 주소로 가입하려면 그 주소도 별도로 허용해야 합니다. 팀원과 업체에는 고정 운영 주소를 공유하세요.

설정을 저장한 뒤 운영 프로그램의 로그인 또는 가입 화면에서 가입한 이메일만 입력하고 **인증 메일 다시 받기**를 누릅니다. 이름·비밀번호를 다시 입력하거나 재가입할 필요가 없습니다. 가장 최근 메일의 링크를 사용하세요. 이미 보낸 메일의 이동 주소는 설정 변경으로 바뀌지 않습니다. 요청을 수락하면 60초 동안 중복 재발송을 막으며, 실제 메일 도착 여부는 받은 편지함과 스팸함에서 확인해야 합니다. 만료·사용된 링크의 오류가 프로그램으로 돌아오면 한국어 재인증 안내를 표시합니다.

앱 코드로 Supabase 프로젝트의 **Site URL** 및 **Redirect URLs**를 변경할 수는 없습니다. 이 서버 설정은 프로젝트 관리자가 대시보드에서 적용해야 합니다.

### 첫 관리자 계정 설정

마이그레이션을 적용한 **후** 앱에서 가입한 실제 이메일로 바꿔 실행하세요. 기존 계정의 비밀번호나 관리자 키를 코드에 저장할 필요가 없습니다.

```sql
do $$
declare
  first_admin_id uuid;
begin
  select id into first_admin_id
    from auth.users
   where lower(email) = lower('YOUR_CONFIRMED_EMAIL@example.com');
  if first_admin_id is null then
    raise exception '먼저 앱에서 회원가입하고 이메일을 확인해 주세요.';
  end if;

  update public.profiles
     set role = 'admin', approved = true, active = true, factory_id = null
   where id = first_admin_id;
  if not found then
    raise exception '가입 프로필이 없습니다. 마이그레이션과 가입 시점을 확인해 주세요.';
  end if;
end $$;
```

첫 관리자 등록은 신뢰할 수 있는 SQL Editor에서만 수행합니다. 이후 사용자 관리는 앱의 관리자 메뉴를 사용하세요. 프론트엔드에서 다른 사람의 Auth 계정·비밀번호를 직접 생성하지 않습니다. 계정 비활성화는 업무 접근을 차단하고 과거 기록을 남기는 방식입니다.

관리자 이관은 나중에도 가능합니다. 현재 관리자가 **사용자·기본 설정 → 사용자 관리**에서 가입한 팀원의 역할을 **관리자**로 지정하고 업무 접근 승인·활성을 확인해 저장합니다. 새 관리자가 로그인한 뒤 기존 관리자를 **본사 직원**으로 변경할 수 있습니다. 현재 로그인한 관리자는 자기 관리자 권한을 직접 해제할 수 없습니다.

| 협력업체 휴가 | 가능 | 가능 | 조회 불가 |
| 품질 검사 대상·수량·상태 | 가능 | 가능 | 배정 스타일 조회 |
| 상의·하의 치수표 | 가능 | 가능 | 배정 스타일만 입력 |
| SIG 가져오기 중 스타일·프로젝트 등록·연결 | 가능 | 가능 | 불가 |
| 스타일 삭제 | 보존 삭제 | 불가 | 불가 |

개인 휴가는 기본적으로 본인만 볼 수 있으며 관리자가 다른 사람의 비공개 휴가를 열람할 수 없습니다. 본사 공유 개인 휴가, 전체 공유 제품 런칭과 본사 전용 협력업체 휴가는 공개 범위를 구분합니다. 본사 직원의 담당 공장 배정은 업무 구분용이며 기존 전체 스타일 조회 권한을 제한하지 않습니다.

승인 전 또는 비활성 계정은 업무 데이터에 접근할 수 없습니다. 공장 계정은 본사 요청·기준 납기·검사 및 최종 컨펌을 수정할 수 없으며 다른 공장 데이터와 첨부파일에 접근할 수 없습니다. 관리자도 기존 샘플 차수·컬러 생산 기록을 제거하지 않고 누적합니다.

### 데이터와 파일

`styles`에는 스타일·샘플·컬러 생산을 하나의 버전 관리 단위로 저장합니다. 프로필, 공장, 프로젝트, 코멘트, 첨부파일, 감사 이력은 별도 테이블입니다. `save_style` RPC는 현재 버전을 확인한 후 권한별 필드를 검증하고 수정 이력을 남깁니다. 다른 사용자가 먼저 저장했으면 저장을 거부하며 현재 편집 내용을 즉시 덮어쓰지 않습니다. 최신 데이터를 확인하고 변경 사항을 다시 반영하세요.

첨부파일은 공개 URL 없이 비공개 `sig-files` 버킷에 저장합니다. JPG·PNG·WEBP·PDF만 파일당 10MB까지 허용합니다. 조회·업로드 권한은 스타일 배정과 계정 상태에 따라 검증합니다. 파일·코멘트는 스타일 또는 특정 샘플 차수에 연결할 수 있습니다.

### 대표 이미지 등록 및 공유

스타일 상세의 **대표 이미지** 영역을 열고, **스타일 기본** 또는 대상 **컬러**를 선택한 뒤 파일과 변경 사유를 입력하고 저장하세요. 관리자·본사 직원이 업로드·교체·연결 해제를 할 수 있고, 외부 공장은 배정된 스타일의 이미지만 볼 수 있습니다. 컬러별 이미지가 있으면 우선 표시하며, 없으면 스타일 기본 이미지로 대체합니다.

대표 이미지는 JPG·PNG·WEBP, 파일당 10MB까지 지원합니다. 투명 배경 컷아웃을 원하면 배경을 제거한 **투명 PNG 파일을 직접 업로드**하세요. 자동 배경 제거는 하지 않습니다. 화면은 원본 비율을 유지하는 `contain` 방식으로 전체 이미지를 표시하고 투명 영역은 체크무늬 배경으로 구분합니다.

이미지는 기존 비공개 `sig-files` 버킷에 저장하며 인증된 다운로드로 표시합니다. 공개 버킷이나 영구 공개 URL을 만들지 않습니다. 교체·연결 해제 후에도 기존 파일은 이력 보존을 위해 남깁니다. 체험 모드에서는 파일을 해당 브라우저의 IndexedDB, 이미지 연결 정보를 localStorage에 저장하므로 다른 사용자와 공유되지 않습니다.

기존 클라우드 프로젝트는 **002 SQL 적용과 새 앱 재배포가 모두 필요**합니다. 마이그레이션이 빠졌어도 기존 업무 화면은 아이콘 대체 표시로 열리며, 상세 화면에 이미지 설정 안내가 표시됩니다. 001을 재실행하지 말고 002를 적용한 후 새로고침하세요.

클라우드 모드의 실시간 이벤트는 Supabase Realtime으로 구독합니다. 브라우저에 표시되는 연결 상태를 확인하세요. 네트워크가 끊긴 동안의 쓰기를 자동 대기열에 저장하거나 재전송하지 않습니다. 실패한 작업은 연결을 회복한 후 다시 실행해야 합니다.

## 추가 업무와 실제 PO 메일

기존 001·002 적용 프로젝트는 **003 SQL을 추가 적용하고 새 앱을 배포**하면 오더 가져오기·부분 출고·고정 작업·캘린더 확장을 사용할 수 있습니다. 실제 PO 메일은 Supabase Edge Function `send-po-email`도 별도로 배포해야 합니다. Resend의 검증된 발신 주소와 서버 전용 `RESEND_API_KEY`, `PO_FROM_EMAIL`, `PO_ALLOWED_ORIGINS`를 설정합니다. 자세한 절차와 예시 파일은 [추가 업무 설정 가이드](docs/OPERATIONS_SETUP.md#실제-메일-서비스-설정)를 확인하세요. 비밀값은 `VITE_` 환경변수에 넣지 않습니다.

PO는 초안 저장과 발송을 구분하고 납기를 실제 메일 제목·본문에 포함합니다. 선택한 기존 스타일 PDF·이미지 파일 1개(최대 10MB)는 실제 메일에 첨부하며, `.eml` 초안 다운로드에는 파일이 들어가지 않습니다. `sent`의 화면 표시는 **발송 접수**이며 메일 서비스의 요청 수락을 뜻합니다. 수신·열람을 보장하지 않습니다. 결과가 불확실하면 자동 재발송을 차단하고 서비스 기록 대조가 필요합니다. 이 개발 작업에서 실제 자격정보를 사용한 원격 PO 메일 발송은 검증하지 않았습니다.

제공된 **SIG_을지.xlsx**의 `대금지급(을)` 양식을 기본으로 포함합니다. **스타일 상세 → 을지·단가**에서 프로젝트 코드·장당 원가·품목 구분을 저장한 뒤 **스타일 상세 상단 → 을지 다운로드** 또는 본사 대시보드의 **을지 양식 다운로드 → SIG 을지 자동 작성 → 을지 다운로드**를 누릅니다. 매번 양식을 업로드할 필요가 없습니다. T열은 사용자가 확인한 **장당 원가 × 실제 입고 수량의 부가세 제외 금액**이며 U·V의 부가세·합계 수식과 원본 표·인쇄 설정을 유지합니다. 원가는 생산을 진행할 때마다 본사 관리자 또는 팀원이 해당 스타일·컬러·프로젝트 기준으로 직접 입력·수정합니다. 오더 CSV나 다른 생산의 원가를 자동 복사하지 않고 기존 마감 금액에서 역산하지 않습니다. 미입력과 명시적 0원을 구분하며 변경 전 단가는 본사 전용 이력에 남깁니다. 프로젝트 코드·원가·입고일 등 필수 정보가 없는 대상은 0으로 채우지 않고 다운로드를 막습니다. 다른 양식은 **다른 양식 · 직접 열 연결**에서 기존 업로드 기능을 사용할 수 있습니다.

005 적용 후 SIG 가져오기 미리보기의 **스타일·프로젝트 등록**으로 없는 품번·컬러를 먼저 등록할 수 있습니다. F열 끝 두 자리만 컬러로 분리하며 **I열은 사용하지 않습니다.** A는 프로젝트 코드, M은 별도 프로젝트 명칭, L은 시즌으로 연결합니다. 공장·본사 담당자와 **직접 선택한 기준 납기일**을 확인하고 기본 정보를 저장한 뒤, 다시 검증하여 **검증된 오더 적용**을 별도로 누릅니다. 이미 등록된 품번의 프로젝트가 다르면 **프로젝트 연결**에서 변경 대상을 확인합니다. 등록 단계는 프로젝트 한 건과 스타일 한 건의 트랜잭션이며, 뒤의 수량 일괄 적용과는 별개입니다.

다시 받은 CSV는 실제로 열어 **CP949, 7행 머리글, 8행의 데이터 1개, 여섯 사이즈 합계 4,138개**를 확인했습니다. UTF-8을 우선 읽고 CP949도 자동 지원하므로 이 CSV를 다시 저장할 필요가 없습니다. 상단 사이즈 요약 행 대신 실제 스타일코드·TOTAL QTY 머리글 행을 우선 인식합니다. F 끝 두 자리는 컬러, AQ~AV는 6사이즈, AY는 합계이며 A/L/M/S/V/W/X/Y 참조를 함께 보관합니다. 선택하지 않은 이미지·부자재 열의 오류 문자열은 가져오기 대상이 아니고, 선택한 열의 수량 오류·Excel 오류 셀과 CSV의 정확한 Excel 오류 문자열은 차단합니다. **오더 엑셀 업로드**의 수량 적용은 등록된 스타일·컬러를 대상으로 하며, 미등록 대상은 위 확인 등록 단계를 먼저 마칩니다. 원본 참조 수정은 **ORDER QTY 원본**, 수기 오더 수정은 **메인 생산**에서 처리합니다. 실제 CSV 검증은 로컬 대조이며 운영 DB에 자동 반영하지 않았습니다.

## 테스트와 빌드

```bash
npm run typecheck
npm test
npx playwright install chromium
npm run test:e2e
npm run build
npm run preview
```

단위·데이터베이스 테스트와 브라우저 테스트는 서로 다른 범위를 검증합니다. PGlite 기반 SQL 테스트는 실제 마이그레이션을 로컬 PostgreSQL 엔진에서 실행해 정책과 RPC를 검증하지만, Supabase 운영 서비스의 Auth 이메일·Storage API·WebSocket까지 검증한 결과는 아닙니다. 실제로 실행한 테스트 수와 한계는 `docs/TEST_RESULTS.md`를 확인하세요.

## Vercel 배포

1. 저장소를 Vercel에 연결하고 Framework Preset을 **Vite**로 선택합니다.
2. Install Command는 `npm ci`, Build Command는 `npm run build`, Output Directory는 `dist`로 설정합니다.
3. `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, `VITE_ENABLE_DEMO=false`를 배포 환경변수에 등록합니다.
4. 빌드·배포 후 실제 도메인을 Supabase Auth Site URL·Redirect URLs에 추가합니다.
5. 관리자·본사·서로 다른 두 공장·미승인 계정으로 [운영 전 확인 목록](docs/IMPLEMENTATION.md#운영-전-실제-서비스-확인)을 수행합니다.

Vite 환경변수는 빌드 시 주입되므로 변경할 때마다 다시 배포해야 합니다. `vercel.json`에는 SPA 경로 처리와 기본 보안 헤더가 포함되어 있습니다. 이 작업에서 원격 배포는 수행하지 않았습니다.
